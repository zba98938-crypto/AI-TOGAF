## 作用范围与易误读处

MSA是架构风格而非产品平台，也不是整个企业架构；不能以代码行数代替业务原子性或把自治解释成无治理。

## 项目应用建议

以下内容是基于本指南证据的建议。输入、输出与步骤不表示本项目已经具备或已经完成；采用前需要结合实际范围、约束和治理权责。

### 需要收集的输入

1. 目标业务功能和价值
2. 原子业务功能分解
3. 服务消费者及数据范围
4. 团队自治、运维和企业约束

### 建议形成的输出

1. ABF与微服务映射
2. 服务契约/API及目录
3. 数据边界和外部供需
4. 工作包、治理和独立部署责任

### 应用步骤

1. 先确定业务功能范围及价值流上下文
2. 分解到交付价值的原子业务功能，识别能力和信息依赖
3. 围绕独立、自包含、单一责任形成服务与数据边界
4. 明确团队开发部署运营责任及企业护栏
5. 以服务契约治理实现并按价值和成本安排迁移

### 决策与验收问题

1. 服务是否对应单一业务责任
2. 能否独立开发部署和变更
3. 外部数据依赖是否显式
4. 自治是否仍遵守企业架构约束
5. 目标是否需要全微服务还是局部采用
