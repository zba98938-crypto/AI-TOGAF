# 精益价值流与业务架构价值流的选择

本地 G178 附录 A.3 的正文与图解释区分两种同名表达。业务架构价值流按利益相关者价值分阶段并关联使能能力；精益价值流分析信息、物料或工作的流动及浪费，单元为具体流程，不能把其流程强行当作业务架构价值阶段或子能力。

精益图的关键决策信息有三层：客户/系统/流程之间的信息流、步骤及排队的工作流、各步骤的前置时间 LT 与加工时间 PT。流程属性保留职能、人员、在制品、LT、PT 和完整准确率 %C&A；未提供数据时标记缺口。网络表达允许与传统精益图不同的布局，但必须有类型、方向、单位、过程顺序和性能信息，不能只输出无指标的客户价值阶段。

按 G178 图 A-3 的解释，若流程确为串行且使用相同边界，可求 LT 总和、PT 总和、活动比 PT/LT、逐步骤条件首次完整准确率乘积。必须先明确时间单位及工作日换算；来源示例的每天8小时不是所有项目默认值。并行、返工环、班次不同或各步骤统计口径不同时不能直接相加和连乘。非加工时间不能全部称为可消除浪费；需要判断等候、运输、检验和必要控制的作用。

项目确定性接口为 analyze.py 的 lean-serial-flow。输入 boundary、rule_evidence、aggregation_rule=serial-conditional-first-pass、steps；每步有唯一 id、lead_time/process_time 的 value 与 unit、complete_accurate_percent 和 evidence。单位支持 minute、hour、working-day；工作日另需 working_hours_per_day。计算保留分钟总值和百分比，不据此推导产能、节拍或投资回报。

修改流程序列或度量后重算并检查瓶颈、等待和质量各自的证据；高 LT、低 %C&A 与高成本是不同问题。优化方案还需验证对客户价值、控制、容量和人员的影响，不能从一个比率自动决定删步骤。
