# 用途与基础设施双入口分析

从哪里识别可放弃/优化用途与设备，如何形成可接受约束？

依据：G242 §3.5.2–3.5.3、表3-3。实际读过对应中文正文与既有逐节审计；本轮未重做英文/原图或外部标准核验。字段为项目操作规范。

## 输入与缺口

组织、服务、业务用途及所评估期间/生命周期边界；原始访谈、使用数据、供应商记录及稳定证据ID；适用目标、职责和组织自定决策规则；未知项显式登记。关键依据未知时给候选表、受影响ID与责任；不编造权重、阈值、估算、批准或实际完成。

## 字段

| 字段 | 含义 |
|---|---|
| name | 机会记录 |

| dependencies | 共享依赖/退出影响 |
| status | 待验证/候选，不能凭分析认定减排 |

## 分析步骤

1. 取得与业务/技术协作的管理授权
2. 从业务用途和高影响基础设施分别建立候选清单
3. 沿应用/数据/设备向下或业务向上追溯共享影响
4. 核实业务接受性并修订非功能要求
5. 明确四类约束理由/检查/复评，并转入方案评审和治理

## 质量与追溯

- 基础设施看似空闲不代表没有业务用途
- 共有设备和数据不能按单一用途全部删除
- 排序不等于碳量核算；未测量不填虚构减排值
- 低技术/人工替代也需同范围全生命周期比较
