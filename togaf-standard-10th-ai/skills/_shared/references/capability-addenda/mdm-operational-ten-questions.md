# C-MDM十问运营诊断

主责 `togaf-information-data`；既有制品 `customer-mdm-model` 的专用规范 `mdm-operational-ten-questions`。

必要输入：本页字段对应的原始业务观察、来源、范围和时点。缺关键证据时保留unknown及缺口，不作通过判断。

## 字段与语义

| 字段 | 含义 |
|---|---|
| question_number | 附录A.2原始问题编号1–10，不能跳过 |
| question | 原问题的完整业务含义 |
| answer | yes/no/partial/unknown/not-applicable-with-reason项目文字判断 |
| evidence_detail | 实际观察或明确未取得证据 |
| consequence | 对C-MDM运营与决策的影响 |
| action | 补证据/改进/复评行动 |
| owner | 行动负责人 |
| scope | 诊断范围与时点 |
| scoring | 明确none；无来源不得合成总分 |

## 分析

1. 保持十问题ID与原问题含义
2. 逐项取证，区分否定、未知、部分和不适用
3. 将缺口映射行动、责任、影响；不得按yes比例冒充成熟度

## 表示与检查

输出对象/完整属性表、所有有类型关系与证据。table输出不进入通用流程图，不等于对应来源图已通过两布局视觉验收。
- 十问各一条且编号不重复
- 未知必须有需补证据行动
- 不适用必须有范围理由
- 无总分/权重/合格线

## 完整例与反例

原料（历史材料已清理） → 分析（历史材料已清理） → 结果（历史材料已清理）。
修改（历史材料已清理）与失败反例（历史材料已清理）。

## 来源边界

- G21B 附录A.1–A.2
- 有草案不等于获批
- 第10问不是强制购买外部数据
