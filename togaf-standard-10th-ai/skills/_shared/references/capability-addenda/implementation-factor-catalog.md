# 实施因素目录

哪些组织文化、转型能力和技能因素改变变革实施安排？

依据：G186 §7.4.1。字段结构与状态编码是项目操作规范，原始指南不随运行读取。

## 输入与缺口

范围、五维语境、所用目标与交付物版本；原始计划/访谈/验收/估算及来源ID；组织授权和容差规则；缺失时不代推。关键依据未知时给候选表、受影响ID与责任；不编造权重、阈值、估算、批准或实际完成。

## 字段语义

| 字段 | 含义 |
|---|---|
| name | 实施因素 |
| unit | 业务单元/企业范围 |
| change_attribute | 文化、转型能力或技能等具体因素 |
| observation | 原始观察与当前情况 |
| evidence_refs | 材料ID |
| effect | 对方案/工作包/时点的实际影响 |
| required_action | 补强动作及其进入条件 |
| owner | 动作责任 |
| timing | 可用窗口与业务约束 |
| confidence | 依据局限，不使用无依据分数 |
| decision_record | 为何采纳此处理及谁仍需确认 |

## 分析步骤

1. 按业务单元与企业层收集转型属性
2. 区分观察事实、解释和未知
3. 将每个因素连接到具体实施工作或选择影响
4. 记录处理动作、责任、窗口与决策理由
5. 资源/文化变化后重新审视路线与风险

### 实施因素决策档案

原始材料（历史材料已清理）组 `factors`。从IF-01/02提取容量、运营窗口、责任文化三项因素；8小时是原料数量相乘所得项目容量，不是TOGAF评分。未知日期阻断排程。

`artifact_id=implementation-factor-catalog`；`profile_id=implementation-factor-catalog-default`；`view_id=v-implementation-factor-catalog-default`。完整表见生成索引（历史材料已清理）。

## 修改与反例

修改：新增演练结果证明东仓已掌握集成。结果：技能缺口可关闭，专家每周8小时容量不自动变多。

反例：只写“成熟度低”无具体观察或证据。结果：factor-evidence-gap。

## 质量与追溯

- 只记录具体因素及影响，不默认文化可用分数衡量
- 访谈说有能力不等于已演练、可用容量或正式承诺

执行证据（历史材料已清理）分别记录模型、生成、修改、反例及表内表达。表格不进行图形视觉验收。工程执行不能替代业务审批和独立业务审查。
