# 架构业务变革与冲刺待办

主责：`togaf-requirements`。决策问题：先处理哪些业务变革，当前团队冲刺承诺哪些架构结果？

本能力包是来源正文的项目操作化规范。原指南没有规定的字段结构、枚举与校验规则均是本实现约定；不把它们称为 TOGAF 强制量表。完整案例均为虚构，审批与实施状态单独记录。

## 入口与输入

制品族 `architecture-backlog`；默认规范 `architecture-business-backlog`。视图实例应按范围/时间点给独立view_id。仅请求本工作产品时读取本页、指定原料与模型即可，无需生成其他制品。

- 原始目标/需求/变更及来源
- 业务优先级及理由
- 依赖与验收条件
- 团队时间盒、目标、可用容量及估算依据

缺失关键输入标记draft和带ID缺口，停止对应通过判断；可以生成明确草稿，不能编造分数、批准、实现或事实。

## 元素、关系与字段

对象类型：guide:backlog_item, guide:sprint。对象ID在修改与两视图中稳定；显示名称可重复但需不同ID/范围。

| 字段 | 语义与要求 |
|---|---|
| backlog_scope | 需求所属的业务变革待办范围；冲刺选择以关系和sprint_id表达；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| business_value | 需求对相关利益人的预期增量价值，允许定性且需来源；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| priority | 利益相关者明确给定的相对顺序；不是量化价值评分；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| priority_basis | 排序依据及提出该判断的来源，不由行号推断；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| owner | 负责澄清、交付或处理该项的角色；不是隐含审批人；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| status | 该工作产品自身的业务流程状态，独立于模型批准/实现状态；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| acceptance_criteria | 判断待办成果达成的可检查条件，须符合原始目标；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| estimate | 带数值或null、单位、依据与estimated/unknown状态的项目估算；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| sprint_id | 所选冲刺稳定ID，未分配为unassigned；多次选择保留history；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| dependencies | 前置待办ID，与guide:backlog_depends_on关系逐项一致；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| source_refs | 支持本条业务内容的来源ID列表，区别指南定义来源；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| history | 按观察时间保留状态/结论与证据的历史，不由后续结果覆盖；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| goal | 整个冲刺的可验证目标；不能由选中事项标题自动代替；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| timebox | 项目声明的开始、结束日期及来源；不是TOGAF固定周期；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| team | 本冲刺共同负责交付的团队范围；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| capacity | 含value、unit、basis的可用投入；未知不能按零处理；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| selected_item_ids | 冲刺选择的待办稳定ID；与选择关系一致；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| planning_status | 该时间点的冲刺规划状态，不代替结果；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| outcome | 冲刺规划时点是否已有成果观察；未观察需明示；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| snapshot_at | 当前规划记录所对应的观察时点；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |

关系：`guide:backlog_depends_on`由依赖方指向前置成果；`guide:scheduled_in`从选中待办指向冲刺，带选择日期；前者不是优先级，后者不表示完成。

## 分析步骤

1. 将每项业务需求归一为稳定ID，保留来源、价值、责任人与验收条件；未知不填零。
2. 依据利益相关者给定排序及依赖确定候选顺序；没有权重时不计算分数。
3. 区分业务变革范围与团队冲刺范围；以相同ID选择近期工作，记录目标与容量。
4. 核对前置工作及所选估算是否在声明容量内；未知估算不能给出容量通过。
5. 以演示证据更新状态；未完成项回流业务待办，保存历史且不自动承诺下一冲刺。

## 输出与表示

输出完整对象属性表、关系表、结论、证据、缺口及交付物视图引用。output_kind=table；不为表格强制绘制流程图。参考结构模式保持稳定字段顺序；适配模式可分节/分页，但每个必要字段和关系必须出现，缺项报ID。没有声称复刻原图。

## 评审

- 业务优先级有证据；编号顺序不等同关系方向
- 每个选中项能关联冲刺目标、估算依据和验收条件
- 依赖无环；依赖可在冲刺内先完成或有既成证据
- 容量单位一致；未知不能计零
- 未完成工作保留原ID并回流；历史冲刺记录不重写

误读：
- 不把速率当项目完成度
- 不固定1–4周为所有组织规则
- 业务待办与冲刺待办是同族两视图，不复制身份或双计制品
- 本例优先级和人日是项目规则，不是TOGAF权重
