# 视角库

为完整利益相关者关注点选择哪些可复用构图规范？

依据：G184 §8.2–8.4；G186 §6.3.1、§9.1.3、附录C表C-1。源文提供方法与参考，字段和状态编码为项目操作规范。公开官方核验以覆盖索引为准。

## 必要输入与缺口

范围和五维语境；原始访谈/计划/测量及定位；授权角色和适用目标版本。逐项登记缺口；未知不等于否或零。缺授权、原口径、时点或关键证据时只能候选，不自动批准、通过或核算。

## 字段与语义

| 字段 | 含义 |
|---|---|
| name | 视角名 |
| concern | 标准关注点 |
| stakeholders | 拥有架构决策权的利益相关者 |
| decision | 待支持的业务决定 |
| construction | 可重复构造视图的方法和筛选规则 |
| required_information | 必需对象、关系、属性、单位等 |
| source_models | 模型/版本引用 |
| view_ids | 实际视图实例ID；视角不是视图 |
| gaps | 缺信息及其影响 |
| selection_reason | 为何覆盖这组关注点 |

## 从原料到结论

1. 从业务原话区分关注点、决策与角色
2. 明确每组问题需要哪些信息并查模型缺口
3. 定义构造规则、筛选范围与状态
4. 关联profile_id和多个实际view_id，检查关注点覆盖
5. 缺信息单列，不以已有图名代替分析

### 云帆物流视角库

原始材料：`viewpoints`（历史材料已清理）。

从VP-01/02/03提取三组决策与关注点，复用成本/过渡/信息模型；成本缺少不确定性资料，预算视图只能作为待补草稿。

完整输入、输出和双布局执行索引见验收记录（历史材料已清理）。`artifact_id=viewpoint-library`，`profile_id=viewpoint-library-default`，示例 `view_id=v-viewpoint-library-default`。

## 修改与反例

修改：新增客户负责人关注签收争议处理。预期：增加争议关注点、证据链信息和专门视角；旧三项不自动覆盖。

反例：只有图名“数据流图”，无关注点/所需信息。应有结果：报告viewpoint-information-gap，不计完成视角。

## 评审与追溯

- 视角定义构造规范，view_id标识具体实例，两者不混同
- 每项授权关注点都有所需信息及构造规则
- 附录C是空白参考库，填入内容是项目分析而非原指南答案

表格的ID、来源、完整字段与结论是输出的组成部分。没有图形，不用SVG/PNG的完成状态代替表格验收。生成、项目规则检验与业务批准分开登记。每次修改保存新模型版本与视图实例引用，不覆盖原始材料。
