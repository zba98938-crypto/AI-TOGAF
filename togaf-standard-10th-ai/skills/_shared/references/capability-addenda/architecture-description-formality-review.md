# 架构描述充分性与正式度评审

主责：`togaf-artifact-review`。决策问题：当前描述是否足以支持指定决策，表达与治理控制是否适合当前目的？

本能力包是来源正文的项目操作化规范。原指南没有规定的字段结构、枚举与校验规则均是本实现约定；不把它们称为 TOGAF 强制量表。完整案例均为虚构，审批与实施状态单独记录。

## 入口与输入

制品族 `architecture-description-formality-review`；默认规范 `architecture-description-formality-table`。视图实例应按范围/时间点给独立view_id。仅请求本工作产品时读取本页、指定原料与模型即可，无需生成其他制品。

- 被评描述及版本
- 具体决策、利益相关者和关注点
- 现有内容与证据
- 项目所需正式控制及裁剪理由

缺失关键输入标记draft和带ID缺口，停止对应通过判断；可以生成明确草稿，不能编造分数、批准、实现或事实。

## 元素、关系与字段

对象类型：guide:description_review。对象ID在修改与两视图中稳定；显示名称可重复但需不同ID/范围。

| 字段 | 语义与要求 |
|---|---|
| description_ref | 被评架构描述及其版本的稳定引用；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| decision | 该描述将支持的具体决策；充分性仅对该决策有效；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| stakeholders | 使用该描述做决策或受到其影响的利益相关者；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| concerns | 本次评审必须回应的具体关注点；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| sufficiency | 对明确决策的sufficient-for-stated-decision/insufficient/unknown文字判断；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| sufficiency_evidence | 逐关注点支持或阻断决策的内容及证据；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| current_formality | 当前采用的术语/记法/版本/审阅等正式控制集合；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| needed_formality | 针对用途所需正式控制集合，必须给裁剪依据；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| formality_fit | 当前控制是否合适、缺少或过度的文字判断；不是批准状态；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| rationale | 将内容/控制与决策联系起来的评审推理；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| actions | 最小必要补充、削减或下一轮验证行动；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| evolution_state | 被评描述所表达的架构演进状态，不当作正式程度；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| approval_state | 描述的批准状态，独立于充分性与正式控制；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| review_rule | 本项目使用的判断约定与出处；不称TOGAF量表；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| source_refs | 支持本条业务内容的来源ID列表，区别指南定义来源；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |

关系：本表的外部引用字段以稳定ID链接相应待办、冲刺、描述或来源；参见完整包model.json。引用不是组成或因果箭头，不可据相邻位置推断。

## 分析步骤

1. 定义该描述要支持的决策与范围，不能泛称“架构是否完整”。
2. 逐关注点核对内容及证据，判断sufficient-for-stated-decision/insufficient/unknown。
3. 独立列当前与所需正式控制（如术语、记法、版本、审阅证据），判断适合、缺少或过度并给理由。
4. 识别复杂系统缺文档或未验证概念就强制全面建模的极端，按当前目的提出最小补充。
5. 演进状态、审批状态另列；不把approved/target当作正式度。

## 输出与表示

输出完整对象属性表、关系表、结论、证据、缺口及交付物视图引用。output_kind=table；不为表格强制绘制流程图。参考结构模式保持稳定字段顺序；适配模式可分节/分页，但每个必要字段和关系必须出现，缺项报ID。没有声称复刻原图。

## 评审

- 充分性与正式度各有独立依据
- 没有来源的等级、数值轴、总分一律不用
- 相对于指定决策而非抽象完整性给结论
- 批准/实现/演进与正式度不同字段
- 修订后复核受影响关注点并保留原判断

误读：
- 形式规范不证明内容充分
- 非正式探索不意味着没有架构
- 本表是正文操作化模板，不是已核验图2-1复刻
- 不同用途结论不能直接互换
