# 企业框架接触与承诺目录

EA应融入哪些已在使用的框架，在哪些接触点补位？

依据：G184 §7.1–7.2、§10.1、§13.1。源文提供方法与参考，字段和状态编码为项目操作规范。公开官方核验以覆盖索引为准。

## 必要输入与缺口

范围和五维语境；原始访谈/计划/测量及定位；授权角色和适用目标版本。逐项登记缺口；未知不等于否或零。缺授权、原口径、时点或关键证据时只能候选，不自动批准、通过或核算。

## 字段与语义

| 字段 | 含义 |
|---|---|
| name | 接触点名称 |
| framework | 框架/企业既有方法及版本 |
| focus | 规划、执行、治理等关注领域 |
| commitment_evidence | 实际使用记录而非口头声明 |
| actual_commitment | 证据支持的采用情况，不使用无依据分数 |
| owner | 流程负责人 |
| touchpoint | 双向接触事件及时点 |
| ea_input | EA消费的信息 |
| ea_output | EA交付的信息 |
| gap | 重叠/缺口 |
| action | 融入或补位动作 |

## 从原料到结论

1. 识别企业实际规划/执行/治理方法、版本与负责人
2. 查批准、资源和连续使用记录区分口头承诺
3. 按成果与信息交接映射接触点
4. 识别已有成果复用、重叠和缺口
5. 协商责任/时点/格式并更新EA路线

## 评审与追溯

- 不把框架目录当企业已采用清单
- 承诺深度由证据叙述，不凭空创建评分
- 框架重叠不表示包含或优先级，优先级须组织规则
