# C-MDM四平台态运营计划

主责 `togaf-information-data`；既有制品 `customer-mdm-model` 的专用规范 `mdm-four-plateau-operations`。

必要输入：本页字段对应的原始业务观察、来源、范围和时点。缺关键证据时保留unknown及缺口，不作通过判断。

## 字段与语义

| 字段 | 含义 |
|---|---|
| state_ref | 命名状态ID，连接v2 states |
| evolution_kind | baseline/transition/target，不是审批状态 |
| mastership | 按属性/范围声明主控 |
| golden_record | 是否可信及分析/运营用途 |
| CRUD_ownership | 谁可创建读取更新删除 |
| propagation | 方向、同步或异步、版本/重试语义 |
| use_cases | 该态可实际运行的用例 |
| operating_gate | 投入该态需验证条件 |
| next_trigger | 演进触发，非凭日期 |
| rollback | 可操作恢复与未决限制 |
| scope | 内核边界与排除 |
| source_mapping | 参考态与本地裁剪关系 |

## 分析

1. 识别当前主控和可用业务能力
2. 分开分析黄金记录与运营主控
3. 逐状态验证用例/质量/授权/恢复/支持条件
4. 选择演进触发，不强制固定四期

## 表示与检查

输出对象/完整属性表、所有有类型关系与证据。table输出不进入通用流程图，不等于对应来源图已通过两布局视觉验收。
- 两个命名transition保留
- 分析黄金态不声称自动双向同步
- 每态有主控/CRUD/可运营门槛/恢复
- 不覆写历史交易事实

## 完整例与反例

原料（历史材料已清理） → 分析（历史材料已清理） → 结果（历史材料已清理）。
修改（历史材料已清理）与失败反例（历史材料已清理）。

## 来源边界

- G21B §4.4、§6.1.1–6.1.2
- 四平台态不是四个过渡状态
- 黄金记录不一定是运营真源

本页字段与检查是正文指导下的项目操作规范，非TOGAF新增固定量表。路径相对skills/_shared，原始指南不随技能复制也可运行本例。
