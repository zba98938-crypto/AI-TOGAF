# C-MDM匹配、合并与人工仲裁

主责 `togaf-information-data`；既有制品 `customer-mdm-model` 的专用规范 `mdm-match-merge-arbitration`。

必要输入：本页字段对应的原始业务观察、来源、范围和时点。缺关键证据时保留unknown及缺口，不作通过判断。

## 字段与语义

| 字段 | 含义 |
|---|---|
| rule | 项目明确匹配规则及来源，不假冒TOGAF阈值 |
| record_refs | 各源记录稳定ID |
| key_comparison | 标识与属性比较，保留未知和冲突 |
| proposal | do-not-merge/manual-review/merge-candidate等候选判断 |
| matching_basis | 推理证据 |
| manual_arbitration | 谁核对什么再如何处理 |
| decision_status | 候选/已决定等业务状态，非真实批准 |
| merge_lineage | 源记录/黄金记录/版本及实际或候选操作 |
| unmerge_plan | 恢复ID/原值/版本及消费者关联的方法 |
| historical_policy | 历史用途与当前真值分离规则 |

## 分析

1. 区分业务键、技术键与姓名属性
2. 按给定规则提出候选，不直接自动合并
3. 人工判定并保留来源/版本/证据
4. 执行前验证可取消合并与历史语义

## 表示与检查

输出对象/完整属性表、所有有类型关系与证据。table输出不进入通用流程图，不等于对应来源图已通过两布局视觉验收。
- 姓名相同不作为唯一合并依据
- merge状态需人工证据及实际谱系
- 概率/阈值必须有项目来源
- 历史原值与源ID保留

## 完整例与反例

原料（历史材料已清理） → 分析（历史材料已清理） → 结果（历史材料已清理）。
修改（历史材料已清理）与失败反例（历史材料已清理）。

## 来源边界

- G21B §3、§5.2.2
- 匹配不等于合并
- 当前黄金值不能覆盖全部历史用途

本页字段与检查是正文指导下的项目操作规范，非TOGAF新增固定量表。路径相对skills/_shared，原始指南不随技能复制也可运行本例。
