# 数字可持续教育与技能计划

所有员工和关键专业角色怎样形成可应用的可持续ICT技能？

依据：G242 §3.3.2、§4.3、§5.2。实际读过对应中文正文与既有逐节审计；本轮未重做英文/原图或外部标准核验。字段为项目操作规范。

## 输入与缺口

组织、服务、业务用途及所评估期间/生命周期边界；原始访谈、使用数据、供应商记录及稳定证据ID；适用目标、职责和组织自定决策规则；未知项显式登记。关键依据未知时给候选表、受影响ID与责任；不编造权重、阈值、估算、批准或实际完成。

## 字段

| 字段 | 含义 |
|---|---|
| name | 教育项目 |
| audience | 全员或具体角色 |
| population | 覆盖人数及范围 |
| current_evidence | 现有知识/培训/实操证据 |
| skill_need | 需补知识与技能 |
| learning_activity | 可执行活动 |
| resources | 已选资源及可用性 |
| application_check | 实际应用能力的验证方式 |
| hr_change | 职位/招聘要求变更 |
| owner | 责任人 |
| status | 覆盖与验证状态 |
| evidence_refs | 原料ID |

## 分析步骤

1. 列全员与重叠专业角色，查当前证据
2. 将普遍意识与角色技能分开
3. 为采购、核算、架构等设计实操任务
4. 安排资源、责任、时间与HR职位/招聘变更
5. 验证理解/实践效果；参加课程不自动提熟练度

## 修改与反例

修改：采购4人完成报告识别和合同练习，但全员理解验证仍未完成。预期：采购能力证据更新，不能把全员状态标完成。

反例：仅20名ICT人员被标全员覆盖。预期：all-staff-coverage-gap。

## 质量与追溯

- 不得仅覆盖ICT员工而漏业务及采购
- 重叠人群不重复计覆盖人数
- 课程/认证建议需核实可用性；本指南例子不代表当前认证有效
- 无评分依据不得自行给技能等级
