# 数字可持续性能力评估

企业可持续ICT能力有哪些具体强项、缺口和改进？

依据：G242 §3.2、§5.2表5-1。实际读过对应中文正文与既有逐节审计；本轮未重做英文/原图或外部标准核验。字段为项目操作规范。

## 输入与缺口

组织、服务、业务用途及所评估期间/生命周期边界；原始访谈、使用数据、供应商记录及稳定证据ID；适用目标、职责和组织自定决策规则；未知项显式登记。关键依据未知时给候选表、受影响ID与责任；不编造权重、阈值、估算、批准或实际完成。

## 字段

| 字段 | 含义 |
|---|---|
| name | 评估项 |
| dimension | G242六维之一 |
| reference_functions | 关联的七功能组/详细功能；多对多 |
| current_evidence | 已做/未证/部分开展的事实 |
| target_need | 组织实际需要 |
| gap | 当前与需要之间的具体缺口 |
| action | 改进动作 |
| owner | 责任人 |
| assessment_rule | 定性或已选成熟度规则及出处 |
| rating | 未选规则时not-scored |
| evidence_refs | 原始材料ID |

## 分析步骤

1. 按六维访谈并核查已开展活动
2. 以七高层功能/35详细功能作非穷尽检查参照，按范围裁剪
3. 区分缺证、未开展和有效执行
4. 只有项目选择成熟度模型后才评分，公开规则来源
5. 把缺口转为有责任和验收依据的改进

## 修改与反例

修改：环境职责经确认并有首次评审记录。预期：治理当前证据更新、缺口缩小，但六维仍无数字评分。
