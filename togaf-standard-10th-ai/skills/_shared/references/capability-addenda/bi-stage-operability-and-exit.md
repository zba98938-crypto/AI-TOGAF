# BI多阶段运营与退出条件

主责 `togaf-information-data`；既有制品 `bi-transition-architecture` 的专用规范 `bi-stage-operability-and-exit`。

必要输入：本页字段对应的原始业务观察、来源、范围和时点。缺关键证据时保留unknown及缺口，不作通过判断。

## 字段与语义

| 字段 | 含义 |
|---|---|
| state_ref | v2命名状态 |
| evolution_kind | 基线/多个过渡/目标区分 |
| data_flows | 源→目标及清洗/原始区别 |
| raw_and_metadata | 原始数据和元数据覆盖 |
| consumers | 逐消费者切换和双供数 |
| incremental_benefit | 该态的新增业务价值 |
| known_gap | 仍未解决的能力与运营代价 |
| operating_exit_gate | 可运营条件与退出验证 |
| legacy_requirement_coverage | 旧需求逐项映射/验证状态 |
| retirement_authorized | 是否获得退出依据；与架构状态不同 |
| cost_basis | 成本的已知/未知依据 |
| schedule_basis | 本地时间依据；指南参考非硬期限 |

## 分析

1. 识别旧系统已满足需求与新价值
2. 按可选过渡定义流向/数据语义和消费者
3. 记录每态收益、缺口和可运营条件
4. 退出前逐项验证旧需求与恢复、治理、元数据

## 表示与检查

输出对象/完整属性表、所有有类型关系与证据。table输出不进入通用流程图，不等于对应来源图已通过两布局视觉验收。
- step1基线/step2–3过渡/step4目标不混同
- 目标未覆盖旧需求不得退旧仓
- 数据流方向随状态变化要表达
- 无成本/时间依据不估算或强定期限
