# 技术与架构债登记

主责：`togaf-change-value`。决策问题：哪些债务应由本产品或EA协调处理，如何追溯偿还并验证关闭？

本能力包是来源正文的项目操作化规范。原指南没有规定的字段结构、枚举与校验规则均是本实现约定；不把它们称为 TOGAF 强制量表。完整案例均为虚构，审批与实施状态单独记录。

## 入口与输入

制品族 `technical-debt-register`；默认规范 `technical-debt-register-default`。视图实例应按范围/时间点给独立view_id。仅请求本工作产品时读取本页、指定原料与模型即可，无需生成其他制品。

- 运营/架构问题与证据
- 受影响产品和跨产品关系
- 原因及业务后果
- 偿还选项、负责人、待办与关闭规则

缺失关键输入标记draft和带ID缺口，停止对应通过判断；可以生成明确草稿，不能编造分数、批准、实现或事实。

## 元素、关系与字段

对象类型：guide:technical_debt。对象ID在修改与两视图中稳定；显示名称可重复但需不同ID/范围。

| 字段 | 语义与要求 |
|---|---|
| kind | 债务的技术/数据/接口/架构性质，允许项目分类；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| affected_products | 受影响产品或服务范围，为EA介入判断提供依据；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| cause | 已知原因或明确假说，必须区别根因证实程度；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| consequence | 对业务、运营、变更或集成的影响，不默认货币化；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| evidence_summary | 债务观察来源、可信度与缺失数值的说明；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| ea_involvement | 由本产品处理或需要EA跨产品协调的路由判断；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| ea_rationale | 该路由判断的范围和后果依据，不是所有债一律EA负责；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| repayment_option | 偿还候选行为及预期解决的问题，不等于已选定执行；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| backlog_refs | 偿还关联的待办ID；空列表表示尚未形成条目；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| owner | 负责澄清、交付或处理该项的角色；不是隐含审批人；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| review_date | 下一复核时点，由项目安排；不代表完成承诺；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| status | 该工作产品自身的业务流程状态，独立于模型批准/实现状态；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| closure_criteria | 项目声明的关闭依据要求，来源和变更必须记录；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| verification_evidence | 修复结果的验证引用，选入计划不能当验证；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| closure_decision | 责任人基于关闭依据的复核结论或not-closed；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |
| cost_or_interest | 仅记录有出处的成本/金额/假设；未知明示，不自造利率或ROI；必填有来源的具体值或显式unknown/待确认，并在缺口中登记；空值不能伪装完成。 |

关系：本表的外部引用字段以稳定ID链接相应待办、冲刺、描述或来源；参见完整包model.json。引用不是组成或因果箭头，不可据相邻位置推断。

## 分析步骤

1. 从问题记录识别债务及来源，区分技术局部问题与架构跨产品问题。
2. 描述影响、原因及不确定性，不凭债务比喻生成利率/金额。
3. 判断是否需EA协调；仅局部债可交产品团队，说明理由。
4. 比较偿还候选与资源/依赖，关联待办、标准、复用或变更记录。
5. 按声明的项目关闭规则收集修复、验证和复核证据，不能凭排期关闭。

## 输出与表示

输出完整对象属性表、关系表、结论、证据、缺口及交付物视图引用。output_kind=table；不为表格强制绘制流程图。参考结构模式保持稳定字段顺序；适配模式可分节/分页，但每个必要字段和关系必须出现，缺项报ID。没有声称复刻原图。

## 评审

- 原因、后果、范围和负责人明确
- EA介入有跨产品或全局理由
- 偿还与待办可追溯
- 未知成本不填零、不自动算利息
- 关闭有验证及复核，原始观察保留

误读：
- 不是所有债务都必须EA处理
- 环境债与技术债不能按名称无条件合并
- 计划偿还不等于已偿还
- 本例关闭门槛是项目规则，不是TOGAF强制公式
