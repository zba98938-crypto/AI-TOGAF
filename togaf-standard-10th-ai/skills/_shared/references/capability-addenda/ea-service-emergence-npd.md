# EA服务N／P／D语境矩阵

主责 `togaf-ea-capability`；既有制品 `ea-service-catalog` 的专用规范 `ea-service-emergence-npd`。

必要输入：本页字段对应的原始业务观察、来源、范围和时点。缺关键证据时保留unknown及缺口，不作通过判断。

## 字段与语义

| 字段 | 含义 |
|---|---|
| service | 同一稳定服务名/ID |
| context | 四DPBoK语境，不是成熟度评分 |
| emergence | N/P/D或本地明确未引入 |
| meaning | N首次/P此前/D加深 |
| local_depth | D必须说明增加何种活动/范围 |
| evidence_detail | 项目服务演进证据 |
| mapping_origin | 项目裁剪或来源逐格转录必须区分 |
| source_cell_status | 原图对应格核实状态 |
| resources | 交付服务所需责任/容量及缺口 |

## 分析

1. 按服务梳理首次出现与后续范围
2. N只用于首次引入，P表示沿用，D要求明确新增深度
3. 记录项目证据与原图证据两个状态，不混称相同

## 表示与检查

输出对象/完整属性表、所有有类型关系与证据。table输出不进入通用流程图，不等于对应来源图已通过两布局视觉验收。
- D有深化说明
- P/D前应有已引入历史
- 未引入不能误用D
- 项目映射不得标为原图逐格复刻

## 完整例与反例

原料（历史材料已清理） → 分析（历史材料已清理） → 结果（历史材料已清理）。
修改（历史材料已清理）与失败反例（历史材料已清理）。
