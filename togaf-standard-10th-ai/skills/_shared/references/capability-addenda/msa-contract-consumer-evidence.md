# 微服务契约与实际／计划消费者

主责 `togaf-application-architecture`；既有制品 `interface-catalog` 的专用规范 `msa-contract-consumer-evidence`。

必要输入：本页字段对应的原始业务观察、来源、范围和时点。缺关键证据时保留unknown及缺口，不作通过判断。

## 字段与语义

| 字段 | 含义 |
|---|---|
| service_id | 逻辑服务稳定ID，版本独立 |
| ABF | 唯一原子业务功能 |
| API | 接口操作及路径 |
| version | 契约版本，不等于架构状态 |
| consumer | 实际/计划消费者身份或明确类别 |
| consumer_status | 计划与实际采用分开 |
| credential | 认证授权和缺口 |
| NFR | 性能/可用/安全的单位、期间、证据或待测状态 |
| address | 可发现的稳定逻辑地址，不暴露真实密钥 |
| compatibility | 版本兼容规则及来源 |
| change_impact | 变更对消费者的具体影响 |
| source | 业务来源定位 |

## 分析

1. 从业务功能界定服务范围和ABF
2. 列契约/API/版本与消费者状态
3. 检查NFR、凭据及地址可发现性
4. 分析新增消费者或字段改变的兼容与治理影响

## 表示与检查

输出对象/完整属性表、所有有类型关系与证据。table输出不进入通用流程图，不等于对应来源图已通过两布局视觉验收。
- 每版本消费者实际/计划明确
- NFR必须有单位/期间/依据或明确待测
- 契约变更必须复核消费者影响
- 一个服务不能偷包多个独立ABF
