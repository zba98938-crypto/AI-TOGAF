# 工作包优先级判定

方法 ID：`work-package-prioritization`。主责：[togaf-migration-roadmap](../../../togaf-migration-roadmap/SKILL.md)。

来源：G186 §8.4、G176 §12.8。定义状态：`project-operational-method`。本方法要求每条权重有来源，否则不出总分。

## 输入

必需：

- 工作包清单
- 评价准则（如收益、风险、成本、依赖、合规紧迫性）
- 每条准则的权重及其来源（裁决记录、政策、历史基准）

可选：各准则的评分量表与锚点。

## 步骤

1. 校验每条权重是否有来源；缺来源的权重标记为无效。
2. 只要存在无效权重，**不计算总分**，输出准则清单与待补来源。
3. 权重齐备时，按准则给每个工作包评分，并记录每条评分的证据。
4. 加权求和，输出排序。
5. 对权重做敏感度检查：单条权重 ±20% 时排序是否翻转，输出敏感区间。

## 输出

| 字段 | 含义 |
| --- | --- |
| `ranking` | 工作包有序列表及总分 |
| `criteria` | 准则、权重、权重来源 |
| `invalid_weights` | 无来源的权重 |
| `sensitivity` | 排序翻转的权重区间 |

## 检查

- 权重无来源却直接加权算出总分 → `missing-evidence`
- 成本类指标未经转换直接当"越高越好"的分值 → `missing-evidence`
- 缺评分证据的条目计入总分 → `measurement-basis-gap`
- 未做敏感度检查却声称排序稳健 → `missing-evidence`

## 误读

- **加权总分不是决策。** 它只是把已说明的偏好算清楚。
- 权重来源可以是一份裁决记录，但不能是"大家认为"。
- 敏感度翻转说明排序不稳，此时应当讨论准则而不是继续精算。

## 反例

| 错误输入 | 预期 | 为什么不通过 |
| --- | --- | --- |
| 五项准则各给 20% 权重，但无任何来源或裁决记录 | `missing-evidence` | 权重无来源却直接加权算出总分 |
