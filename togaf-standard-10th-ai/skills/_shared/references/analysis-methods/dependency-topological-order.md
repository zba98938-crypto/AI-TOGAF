# 工作包依赖拓扑排序

方法 ID：`dependency-topological-order`。主责：[togaf-migration-roadmap](../../../togaf-migration-roadmap/SKILL.md)。

来源：G186 §8、G188 §3.2。定义状态：`project-operational-method`。本方法给出可复核的排序规则，不证明任何工作包已获授权。

## 输入

必需：

- 工作包清单（稳定 ID + 名称）
- 依赖边（`source`、`target`、`kind`）
- 每条依赖的 `hard` / `soft` 标记

可选：

- 资源约束与并发上限
- 外部截止日期

缺 `hard`/`soft` 标记时，只能输出候选序并登记缺口，不能声称关键路径。

## 步骤

1. 用工作包清单建立节点，用依赖边建立有向图。
2. 检测环。存在环时**立即返回环清单**（`cycle`），不输出顺序。
3. 按拓扑序分批：无未满足前置的节点进入当前批次。
4. 标记软依赖：软依赖不阻塞批次，但需在结果中列出被跨越的软边。
5. 输出批次、每批的并行度、被跨越的软边清单。

## 输出

| 字段 | 含义 |
| --- | --- |
| `batches` | 有序批次，每批为工作包 ID 列表 |
| `cycles` | 检测到的环（每个环为节点序列） |
| `crossed_soft_edges` | 本排序跨越的软依赖边 |
| `blocked` | 因缺依赖标记而未纳入排序的工作包 |

## 检查

- 存在环却直接给出顺序 → `cycle`
- 把软依赖当硬依赖，导致批次被人为串行 → 报告但不算失败，需在结果中标明
- 依赖端点指向不存在的工作包 → `dangling-reference`
- 缺 `hard`/`soft` 标记仍声称关键路径 → `missing-evidence`

## 误读

- 拓扑序**不是**时间计划；它只说不违反依赖的最早可行分组。
- 软依赖被跨越不代表零风险，只代表不构成硬阻塞。
- 批次内并行度受资源约束限制，本方法不计算资源可行性。

## 反例

| 错误输入 | 预期 | 为什么不通过 |
| --- | --- | --- |
| 依赖图 A→B→C→A 成环，仍输出 A、B、C 的顺序 | `cycle` | 存在环却直接给出顺序，未报告环 |
