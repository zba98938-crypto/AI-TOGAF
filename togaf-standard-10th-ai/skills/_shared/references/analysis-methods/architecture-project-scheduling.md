# 架构项目分解与排程

方法 ID：architecture-project-scheduling。主责：togaf-architecture-workbench。来源：G188 §3.2。步骤与输出结构是本技能的操作约定。

## 输入

- 成果范围
- 活动
- 依赖
- 工期与资源

## 实际分析步骤

1. 按成果分解
2. 估算活动
3. 安排资源和里程碑
4. 在完整输入下分析关键路径

每一步保留输入、转换与结果的追溯。先进行业务判断并记录理由，再把对象和关系写入模型；脚本只在已给出完整规则时计算。

## 输出与评审

- [架构项目资源与进度](../capabilities/architecture-project-schedule.md)

- 不完整依赖不能支持确定关键路径

记录阻断缺口；无明确规则不计算数值或形成确定结论。

修改分析时保留范围、模型版本和稳定 ID，并对输入变化重算或重评。评审分别核对事实证据、方法适用性、运算及结论，不能仅检查文件生成成功。
