# 业务场景前提验证与归一化

方法 ID：scenario-elicitation。主责：togaf-vision-scenarios。来源：G176 §3.2–3.3。步骤与输出结构是本技能的操作约定。

## 输入

- 前提
- 访谈与问题材料

## 实际分析步骤

1. 拆分陈述
2. 亲和归类
3. 保持原始到归一化映射
4. 验证前提
5. 形成需求

每一步保留输入、转换与结果的追溯。先进行业务判断并记录理由，再把对象和关系写入模型；脚本只在已给出完整规则时计算。

## 输出与评审

- [业务场景文档](../capabilities/business-scenario-document.md)

- 前提未经检验时不能当业务事实

记录阻断缺口；无明确规则不计算数值或形成确定结论。

修改分析时保留范围、模型版本和稳定 ID，并对输入变化重算或重评。评审分别核对事实证据、方法适用性、运算及结论，不能仅检查文件生成成功。
