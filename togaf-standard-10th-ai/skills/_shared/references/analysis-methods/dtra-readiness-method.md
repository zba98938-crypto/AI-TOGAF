# DTRA 就绪度评价与后果

方法 ID：dtra-readiness-method。主责：togaf-ea-capability。来源：G212 §5、附录A。步骤与输出结构是本技能的操作约定。

来源复核：G212 英文附录 A 的图 A-1 给出七个有序响应等级，但原图没有数值 1–7，也没有“低于 6 需管理关注”的阈值。若项目把等级编码为整数，并按阈值形成关注因素和就绪类型，须在分析输入中显式提供 `attention_min_rating` 与 `attention_threshold_evidence`；否则计算器只返回因素完整性和阻断项，不赋就绪类型。此处的数值和阈值属于虚构项目规则，不是 TOGAF 规定。详见当前来源对照（历史材料已清理）。

## 输入

- 七级问卷
- 因素
- 参与者与共识证据

## 实际分析步骤

1. 逐因素评估
2. 识别管理关注
3. 分析主要后果
4. 安排因素递进

每一步保留输入、转换与结果的追溯。先进行业务判断并记录理由，再把对象和关系写入模型；脚本只在已给出完整规则时计算。

## 显式规则计算入口

模型 `analyses` 条目的 `method_id` 使用 `dtra-factor-review`，并提供相应规则、量尺和输入引用。执行 `python scripts/analyze.py model.json --evaluate <analysis-id>`；该命令相对于共享工具目录。计算器只执行已声明规则，不代替证据、方案权衡或批准。输入结构与完整虚构案例见 analysis_cases.py（历史材料已清理） 和 [评价操作手册](../assessment-handbook.md)。

修改分析时保留范围、模型版本和稳定 ID，并对输入变化重算或重评。评审分别核对事实证据、方法适用性、运算及结论，不能仅检查文件生成成功。
