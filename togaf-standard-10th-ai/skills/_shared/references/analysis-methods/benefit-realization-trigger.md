# 收益实现复评触发

方法 ID：`benefit-realization-trigger`。主责：[togaf-migration-roadmap](../../../togaf-migration-roadmap/SKILL.md)。

来源：G184 §10.1.7、G184 §11.4。定义状态：`project-operational-method`。本方法只比较实测与目标；没有实测值就不比较。

## 输入

必需：

- 目标值、单位、期间、基线
- 实测值、测量窗口、测量方法
- 归因边界（哪些变化可归因于本次变革，哪些是外部因素）

可选：历史多期实测值、对照基线。

## 步骤

1. 对齐目标与实测的口径：单位、期间、合并范围必须一致，不一致即停。
2. 无实测值时输出"未观测"，**不得用计划值代替**。
3. 计算偏差：绝对偏差与相对偏差，并记录计算口径。
4. 检查归因边界：把可归因部分与外部因素分开列出。
5. 按观测窗判定是否触发复评（触发条件须事先声明）。

## 输出

| 字段 | 含义 |
| --- | --- |
| `observed` | 是否有实测值 |
| `deviation` | 绝对偏差、相对偏差与计算口径 |
| `attribution` | 可归因部分与外部因素 |
| `trigger` | 是否触发复评及触发的规则来源 |

## 检查

- 把计划值当实测值计算偏差 → `measurement-evidence-gap`
- 目标与实测的单位或期间不一致仍相减 → `measurement-period-gap` 或 `measurement-basis-gap`
- 触发条件未事先声明就宣布触发 → `missing-evidence`
- 未区分归因与外部因素即声称变革见效 → `missing-evidence`

## 误读

- **计划收益不是收益。** 它只说明当时的预期。
- 偏差方向与大小都需归因，正值也不等于变革有效。
- 一次观测不构成趋势；趋势需要多期同口径数据。

## 反例

| 错误输入 | 预期 | 为什么不通过 |
| --- | --- | --- |
| 以计划收益 12% 作为实测值参与偏差计算 | `measurement-evidence-gap` | 把计划值当实测值计算偏差 |
