## 决策与原始业务资料

38 条应用功能中，哪些有运行证据？当来源图的标签与本地定义冲突时怎么处理？

| 证据 ID | 原始材料 |
|---|---|
| `mda-1` | 没有 C-MDM 功能的运行证据。 |
| `mda-2` | 管家提出"取消合并"需求，但尚未演练。 |
| `mda-3` | 38 条应用功能均为参考条目，尚无实现证据。 |
| `mda-4` | 推送事件的第三操作存在冲突：本地"定义"与图标签标注为 `Delete`。 |

## 来源规则与项目规则

1. 来源方法（G21B）：应用功能覆盖需有运行证据，参考条目本身不是覆盖。
2. 来源方法：主数据的合并、拆分与传播是不同操作，语义不可互换。
3. 项目规则：**遇到来源图标签与本地定义冲突时，登记冲突并保留双方**，不得择一覆盖（`mda-4`）。
4. 项目规则：冲突未裁决前，涉及该操作的功能一律记未知，不得按任一方实现承诺。

## 转换与推理

1. **待逐条登记的 38 条参考功能**：因 `mda-1` 无运行证据，38 条全部记未知（不是不适用，也不是计划）。

| 判定 | 条数 |
| --- | --- |
| 已见 | 0 |
| 计划 | 0（`mda-2` 的需求尚属提出阶段，未形成计划） |
| 未知 | 38 |
| 不适用 | 0 |

2. **处理冲突**：`mda-4` 的第三操作有两种解释——"定义/修改"或"删除"。登记为 `MDA-CONFLICT-1`，两条解释并列保留。
3. **阻断下游承诺**：在冲突未裁决前，任何涉及该操作的实现承诺（如"支持删除传播"）都不得给出，因为两种解释的后果完全不同。
4. **区分需求提出与计划**：`mda-2` 的"取消合并"是需求提出，尚无时间、责任人、验收，因此不构成计划项。

5. **冲突的处置规则：保留双方，不择一**。`mda-4` 的推送事件第三操作有两种解释：本地表写"定义"、图标签写 `Delete`。处置要点：
   - 登记 `MDA-CONFLICT-1`，**两条解释并列保留**
   - 不选一个"看起来更合理"的
   - 冲突未裁决前，任何依赖该操作的承诺都不给出

   理由：两种解释的后果**完全不同**——"定义/修改"与"删除"有不同语义，是否幂等或传播到下游取决于具体契约，不能由操作名称直接推断。选错一边，实现方向就错了。

6. **冲突不是"数据质量问题"，是语义未定**。把冲突当作"待清洗的脏数据"会导致随手填一个默认值。正确处置是**把它当作待裁决的语义问题**，交给有权裁决的人（本例为英文原文核实后由项目决定）。

7. **需求提出与计划的界线**。`mda-2` 的"取消合并"是管家提出的需求，但：
   - 无时间
   - 无责任人
   - 无验收条件
   
   三项缺任一即不构成计划项。**"有人提了"不等于"安排了"**，更不等于"已具备"。

8. **38 条全未知的诚实表达**。`mda-1`/`mda-3` 明说没有任何运行证据。此时四类判定为 0/0/38/0。这个分布本身就是结论：**本轮未取得任何 C-MDM 应用功能的实现/运行证据**，不等于确认尚未开始实现。不需要算覆盖率也能看出这一点。

## 修改演练

**情景一：冲突裁决为"定义/修改"**。`MDA-CONFLICT-1` 关闭，"删除传播"相关条目**仍为未知**——裁决了第三操作的含义，不等于具备了该操作的实现。**不得回填为"不具备"**，无证据只说明未知。

**情景二：冲突裁决为"删除"**。需同时确认两件事：
- 删除是否传播到下游消费者
- 是否可撤销（删除通常不可逆）

   若无撤销或替代恢复/留存处置，应登记计划的前置缺口；可计划补设计，但不得承诺已可实施。这与"定义/修改"分支的后果差别，正是冲突必须先裁决的原因。

**情景三：某条功能补齐运行证据**。该条从未知转为已见。但**只有该条**变化，其余 37 条不因同属一个功能组而连带升级。粒度规则与宏观行继承禁令一致。

**影响范围**：情景一、二改变冲突状态与下游承诺范围；情景三改变单条判定。三种情形下"38 条全登记"与"无证据即未知"的规则不变。

## 冲突处置与计划判定

- 冲突保留双方，不择一（定义 vs 删除）
- 冲突未裁决前不给任何依赖该操作的承诺
- 计划需时间、责任人、验收三项齐备
- 需求提出不等于计划
- 38 条全未知时不给覆盖率

## 反例与输入不足

- **错误做法**：按图标签把第三操作实现为删除并承诺传播。冲突未裁决。预期 `missing-evidence`。
- **错误做法**：把"管家提出取消合并"写成"已计划取消合并"。需求提出不等于计划。预期 `missing-evidence`。
- **错误做法**：38 条全未知时报"应用功能覆盖率 0%"。未知不等于不满足。预期 `measurement-basis-gap`。
- **错误做法**：冲突时选一个"更常见"的解释（如默认按删除处理）。两种解释后果不同，不可择一。预期 `missing-evidence`。
- **错误做法**：裁决冲突后，把相关条目直接标为"已具备"。裁决语义不等于实现功能。预期 `approval-without-evidence`。
- **错误做法**：某条功能补齐证据后，把同组其他条目一并升级。粒度不可继承。预期 `core-vocabulary-override`。
- **错误做法**：把冲突当作"脏数据"随手填默认值以完成登记。冲突是语义未定，不是数据清洗问题。预期 `measurement-basis-gap`。

**输入不足**：`mda-1` 无运行证据，38 条本轮无法关闭。`mda-4` 的冲突需英文原文核实，材料未给核实结果，`MDA-CONFLICT-1` 保持未裁决。材料未给 38 条的完整清单，故不逐条列举。
