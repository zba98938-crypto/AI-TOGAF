# 收益实现复评触发：差错率从 1.8% 到 1.1%，算不算达标

虚构集团的新结算系统承诺：上线 12 个月内把结算差错率从 1.8% 降到 0.6%。上线第 9–12 月实测 1.1%，同期还新增两条业务线、业务量增长 40%。本案例演练如何计算偏差、如何守住"无实测值不比较"这条底线，以及为什么改善、达标与因果归因必须分开。

所有业务材料、数值、观测窗与触发规则均为虚构教学材料；触发条件"偏差超过 50% 即触发复评"是**事先声明**的项目规则，不是 TOGAF 默认值。

方法：`benefit-realization-trigger`。来源方法：G184 §10.1.7、§11.4。
入口：[benefit-realization-trigger](../analysis-methods/benefit-realization-trigger.md)。

## 决策与原始业务资料

要回答：**这次变革达到承诺了吗？如果没有，是整体问题还是局部问题？要不要启动复评？**

| 证据 ID | 原始材料 |
|---|---|
| `BEN-1` | 目标值：结算差错率 **0.6%**（承诺：上线 12 个月内达成）。 |
| `BEN-2` | 基线：上线前 6 个月均值 **1.8%**。 |
| `BEN-3` | 实测：上线后第 9–12 月，结算差错率 **1.1%**。 |
| `BEN-4` | 观测窗：**4 个月**（第 9–12 月）；测量方法为单位结算笔数中的差错笔数占比。 |
| `BEN-5` | 外部因素：同期新增两条业务线，业务量增长 **40%**，新业务差错率本身偏高。 |
| `BEN-6` | 分组材料：存量业务差错率为 **0.7%**（仍高于目标）；有人估称新增业务贡献约 **0.4 个百分点**，但未给业务量权重、分组差错笔数与归因方法，不能视为已证实拆分。 |
| `BEN-7` | 触发条件（**事先声明**）：实测值与目标偏差**超过 50%** 即触发复评。 |

## 来源规则与项目规则

1. **来源方法（G184 §10.1.7、§11.4）**：本方法只比较**实测与目标**；**没有实测值就不比较**。
2. **来源方法**：口径对齐是第一步——单位、期间、合并范围必须一致，不一致即停。
3. **来源方法**：偏差须同时给绝对偏差与相对偏差，并记录计算口径。
4. **来源方法**：归因边界须显式——可归因部分与外部因素分开列出。
5. **来源方法**：触发判定按**事先声明**的条件执行；事后调整阈值无效。
6. **项目规则**：**不得用计划值、目标值或估算值代替实测值**（方法明示"计划值不是观测结果"）。
7. **项目规则**：观测窗过短或处于迁移扰动期时，只能报"未观测到稳定改善"，不得得出效果结论。

## 转换与推理

1. **口径对齐（第 1 步）**：目标 0.6% 与实测 1.1% 都是按结算笔数计算的差错率。项目暂按目标适用于第 9–12 月全部业务的合并差错笔数/结算笔数作描述性比较；目标的验收窗口、是否包含新增业务及四个月是否按笔数汇总尚待确认，故不是已确认的同范围验收。若实测用的是"投诉率"或"对账差异率"，则不同口径，必须停止比较。

2. **确认有实测值**：`observed=true`。这一步不能跳过——若只有计划收益 12%，则 `observed=false`，只报"未观测"，**不进入偏差计算**。

3. **偏差计算（第 3 步）**：
   - 相对目标偏差 = (1.1 − 0.6) / 0.6 = **+83.3%**
   - 相对基线改善 = (1.8 − 1.1) / 1.8 = **38.9%**
   - 绝对偏差 = 1.1 − 0.6 = **+0.5 个百分点**
   
   三个数各说一件事：相对目标偏差说"离承诺多远"，相对基线改善说"比过去好了多少"，绝对偏差说"差几个点"。**只报其中一个都会误导。**

4. **归因拆分（第 4 步）**：存量组差错率 0.7% 不是对整体差错率的百分点贡献，不能直接与估算 0.4pp 相加。整体率应为 `w_old×r_old + w_new×r_new`，权重须取同窗各组结算笔数占比。业务量增长 40% 不等于新增业务占比 40%；缺分组笔数和对照证据，**不能排除系统改造问题，也不能把差异归因于新业务接入**。

5. **触发判定（第 5 步）**：83.3% > 50% ⇒ **触发复评**。注意这是按 `BEN-7` 事先声明的阈值判的，不是事后觉得"83% 太高了"才定。

6. **按暂定可比口径，整体与存量均未达目标**：1.1% > 0.6%，0.7% > 0.6%。整体低于历史基线只能描述观测改善，不证明系统改造的因果效果。复评应同时核查测量口径、系统改造与新业务接入，不预先排除任何一方。

偏差计算（相对目标、相对基线、绝对差）为可复核算术。**但"是否触发复评"由事先声明的阈值与运算符决定，不由计算器裁量**；归因拆分（存量 vs 新增）为定性判断，没有适用的统一计算器。

本案例有适用的独立偏差算术断言，但不借用其他方法计算器。**方法输出的边界**：按暂定口径报告偏差与条件式复评触发；不把描述性改善当作因果收益，不把未确认的目标范围当作正式验收。

## 修改演练

改动一处输入：观测窗改为上线后第 4–6 月（早期），实测值 **1.6%**。

- 相对目标偏差 = (1.6 − 0.6) / 0.6 = **166.7%**
- 相对基线改善 = (1.8 − 1.6) / 1.8 = **11.1%**
- 触发判定：166.7% > 50% ⇒ **同样触发复评**。
- **但归因不成立**：早期数据受迁移期扰动影响，无法把 1.6% 拆成"存量 + 新增"。此时只能报"**未观测到稳定改善**"，**不能得出"改造无效"的结论**。
- 影响：`value-realization-assessment` 的结论措辞、复评对象的选择（仍为"口径、系统与接入均待核查"）、是否需要追加工作包。

**这个演练的意义**：同一个"触发复评"的结论，在不同观测窗下的**可解释性完全不同**。触发是机械的，归因不是。

反向演练：若把目标从 0.6% 放宽到 1.2%，则相对目标偏差 = (1.1 − 1.2)/1.2 = **−8.3%**，实测优于目标，"达标"。**但放宽目标属于变更承诺**，必须作为独立决策记录并说明依据（谁批准、为什么、对基线承诺的影响），不能在同一个偏差计算里偷偷改 `BEN-1`。

## 偏差的三种口径

- 相对目标偏差 = (实测 − 目标) / 目标
- 相对基线改善 = (基线 − 实测) / 基线
- 绝对偏差 = 实测 − 目标（同单位）
- 三者各说一件事，只报一个会误导
- 无实测值时不进入偏差计算

## 反例与输入不足

- **错误做法**：以计划收益 12% 作为实测值参与偏差计算。计划值不是观测结果，且收益率 12% 与差错率目标不是同一指标。预期 `measurement-evidence-gap`。正确处置：`observed=false`，只报未观测，等待实测数据。
- **错误做法**：实测用"投诉率"、目标用"差错率"，仍直接相减。口径不一致必须停止比较。预期 `measurement-basis-gap`。
- **错误做法**：只报相对目标偏差 83.3%，不报相对基线改善 38.9%。单一口径会掩盖"其实改善了不少"这一事实。预期 `measurement-basis-gap`。
- **错误做法**：把 1.1% 全部归因于新业务，或以 0.7% + 0.4pp 直接证明归因。缺分组权重及对照，归因边界缺失。预期 `missing-evidence`。
- **错误做法**：观测到 83.3% 后，把触发阈值从 50% 改为 90%，从而"不触发"。事后调整阈值。预期 `approval-without-evidence`。
- **错误做法**：因 4 个月观测窗数据就宣称"长期效果已确认"。观测窗不足。预期 `measurement-basis-gap`。

**输入不足**：`BEN-5` 只给"业务量增长 40%"与"新业务差错率偏高"，**未给新增业务的分线差错率明细**，因此 0.4pp 只是未经证实的估称，不是可加到存量组率上的实测贡献（`BRT-GAP-2`）。`BEN-4` 的 4 个月观测窗未说明是否覆盖完整业务周期（含季末结算高峰），长期趋势无法判断（`BRT-GAP-1`）。材料未给对照基线（同期未改造的同业或内部对照组），因此无法排除行业性波动。
