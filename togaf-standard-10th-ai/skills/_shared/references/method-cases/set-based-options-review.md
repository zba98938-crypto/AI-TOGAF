# 集合式并行方案逐轮评估：先并行探，再淘汰，淘汰了还能重开

虚构市民图书馆要在两个子系统上选方案：通知子系统可在"集中队列 A"与"事件流 B"之间选，目录子系统可在"已测 API C"与"夜间文件 D"之间选。本案例演练集合式并行工程（SBCE）：如何同时推进多个备选、如何逐轮用证据淘汰、以及为什么淘汰必须保留历史且可以**带新证据重开**。

所有业务材料、人物、实验数值与规则均为虚构教学材料（`LAB-1`–`LAB-3`）。**500 毫秒是项目阈值，180/800 毫秒是实验观测值，均来自本例项目材料，不是 TOGAF 默认值。**

方法：`set-based-options-review`。来源方法：G20F §4.6。
入口：[set-based-options-review](../analysis-methods/set-based-options-review.md)。
素材：原料（历史材料已清理）、执行审计（历史材料已清理）。

## 决策与原始业务资料

要回答：**四个备选怎么并行推进、每轮凭什么保留或淘汰、淘汰后还能不能回来？**

| 证据 ID | 原始材料 |
|---|---|
| `LAB-1` | 通知子系统可保留集中队列 A 或事件流 B；目录子系统可用已测 API C 或夜间文件 D。A/C 首轮可实现分钟级回执；**D 无法满足实时查验**。**B 的恢复能力尚待实验。** |
| `LAB-2` | 第二轮 A 端到端压测 95 分位延迟 **180 毫秒**，C 契约兼容；项目约定预算与恢复窗口均满足。**B 恢复演练暂未满足项目要求，保留原始失败日志。** |
| `LAB-3` | 变更实验扩大到 **47 馆并发**，A 延迟 **800 毫秒超出项目 500 毫秒要求**；**B 的新恢复方案通过演练**且与 C 的新接口契约兼容。规则和实验值均属项目。 |

## 来源规则与项目规则

1. **来源方法（G20F §4.6）**：多个备选应在信息不足时**并行推进**，而不是过早收敛到一个方案；收敛依据是可追溯的证据，不是偏好。
2. **来源方法**：每一轮评估需记录假设、评估结论、证据、决策者与决策理由；淘汰是**有证据的动作**。
3. **来源方法**：证据变化导致原淘汰不成立时，应**保留原记录并重开**，不得改写历史。
4. **来源方法**：选定组合后须检查**跨子系统约束**，不能只看单子系统最优。
5. **项目规则**：响应时间阈值 500 毫秒、预算与恢复窗口为本例项目规则（`LAB-2`、`LAB-3`）。
6. **项目规则**：`automatic_approval` 恒为 `false`——`selected` 是**项目分析选择**，不是正式批准。

## 转换与推理

1. **第一轮：并行保留，先剔一个明显不合格的**。`LAB-1` 说 D 无法满足实时查验，因此 D 在**第 1 轮**即淘汰，`decision_reason` 写"响应窗口不符"，`new_evidence_refs=["LAB-1"]`。A、B、C 继续。注意：B 的恢复能力"尚待实验"——这是**未知**，不是"不行"，故不淘汰。

2. **第二轮：A 领先，B 淘汰**。`LAB-2` 给 A 180 毫秒（满足项目条件）⇒ `selected`；C 契约兼容 ⇒ `selected`；B 恢复演练未达标 ⇒ `eliminate`，`decision_reason` 写"恢复演练未满足项目要求（具体超限数值未给）"，`new_evidence_refs=["LAB-2"]`，并**保留原始失败日志**。此时 `selected_ids=["A","C"]`，`eliminated_ids=["B","D"]`，`iteration_count=2`。

3. **第三/四轮：A 被推翻，B 带新证据重开**。`LAB-3` 把并发扩到 47 馆：A 延迟 800 毫秒 > 500 毫秒 ⇒ A 在第 3 轮 `eliminate`，理由"新增 47 馆负载证据推翻旧评估"。B 的新恢复方案通过演练 ⇒ B 在第 4 轮 `selected`。结果 `selected_ids=["B","C"]`，`eliminated_ids=["A","D"]`，`iteration_count=4`。

4. **重开不是"撤回"，而是新增一条迭代记录**。B 在第 2 轮有一条 `eliminate`（迭代 2），在第 4 轮有一条 `selected`（迭代 4）。**两条记录同时存在**，因为评估对象变了（恢复方案换了）。若把第 2 轮那条改成 `selected`，就伪造了"当时就看好 B"的历史。

5. **A 的身份也变了**：第 2 轮 A 是 `selected`（迭代 2），第 3 轮变成 `eliminate`（迭代 3）。同样两条并存。`latest_options` 只呈现**每个备选的最后一轮**，但完整历史可从迭代序列复原。

6. **跨子系统约束必须单独检查**。A/C 兼容、B/C 兼容，都是**跨子系统**结论。`constraint_review` 字段记录这一点；若 B 与 C 的新契约不兼容，即使 B 单子系统最优也不能选。这是 SBCE 与"逐项择优"的根本区别。

7. **`automatic_approval=false` 与 notice**。notice 写"selected 是项目分析选择，不是正式批准；未建模的子系统耦合仍须评审"。这句话把方法的输出边界钉死在"分析结论"上。

本方法采用定性判断与追溯演练，没有适用的统一计算器。**本案例不对方案打分、不做加权排序**：正式选择需项目阈值与跨子系统兼容证据；本例历史 selected 只记录项目候选选择，不能宣称B/C已全面达标，不由综合得分决定。阈值比较只是必要条件，不是充分条件。

## 迭代记录的结构

每一轮评估都要留下可复核的一项，缺任一项即无法解释"为什么当时这样判"：

| 字段 | 作用 | 本案实例（B 的淘汰） |
| --- | --- | --- |
| `option_id` | 哪个备选 | `B` |
| `iteration` | 第几轮 | `2` |
| `hypothesis` | 当时在验证什么 | 明确契约与恢复策略可满足回执要求 |
| `assessment` | 观察到什么 | 恢复实验未满足项目要求 |
| `evidence_refs` | 依据哪份材料 | `LAB-2` |
| `decision_owner` | 谁判的 | 架构与运营评审组 |
| `status` | 保留/淘汰/重开/细化 | `eliminate` |
| `decision_reason` | 为什么 | 恢复演练未满足项目要求（具体超限数值未给） |
| `new_evidence_refs` | 本轮新出现的证据 | `LAB-2` |

**`new_evidence_refs` 是淘汰的门槛**：没有新证据不得淘汰。这条把"我们觉得不行"和"证据显示不行"分开。

**同一备选可以有多条记录**。B 在第 2 轮 `eliminate`、第 4 轮 `selected`，两条并存。判定"当前状态"时取**最大 iteration** 那条；但**历史判定不作废**——第 2 轮时确实不满足条件。

## 约束检查

跨子系统约束是独立的一步，不能与单子系统择优合并：

| 约束 | 状态 | 依据 |
| --- | --- | --- |
| A 与 C 兼容 | 满足 | `LAB-2` |
| B 与 C 兼容 | 满足（B 新恢复方案后） | `LAB-3` |
| 未建模耦合 | **未评审** | — |

`constraint_review` 必须存在。若缺失，即使各子系统都选了最优，组合也可能不可行——**本地最优不保证全局可行**。

## 修改演练

改动 LAB-3 中两个观测：假设 A 在 47 馆并发下降到 400 毫秒（仍在 500 毫秒内），且 B 的恢复方案未通过。

- A：第 3 轮**不淘汰**，保持 `selected`（迭代 3 记录"47 馆并发 400ms，满足项目条件"）。
- B：第 2 轮淘汰后**不重开**，`eliminated_ids` 仍含 B。
- `selected_ids` 回到 `["A","C"]`，`iteration_count` 仍为 4（轮次发生了，只是结论不同）。
- **关键**：不能因此把 `LAB-3` 的证据"作废"。若真实材料就是 800ms，写 400ms 是伪造实验值；本演练只是说明**同一套流程在相反证据下会给出相反结论**，流程本身不带倾向。
- 影响视图：`set-based-options-iteration` 的 A、B 两个备选行与其 `status`、`decision_reason`、`new_evidence_refs`。

反向演练：若 `LAB-3` 只给"B 恢复通过"而不给"47 馆并发"数据，则 A 不该被推翻——**推翻需要有直接触及 A 的证据**，不能因为"B 变好了"就推断"A 不行了"。这是 SBCE 里最常见的推理错误。

## 反例与输入不足

- **错误做法**：删掉 `reopen` 类型的迭代记录，只保留最终选择。重开历史被抹除。预期 `sbce-reopen-evidence-required`。
- **错误做法**：把约束状态批量改为 `unknown` 却仍保留 `selected_ids=["B","C"]`。组合兼容性未确认即宣称选定。预期 `sbce-selected-set-not-compatible`。
- **错误做法**：某条淘汰记录的 `new_evidence_refs` 为空——"我们觉得不行"不是证据。预期 `sbce-elimination`。
- **错误做法**：同一备选同一轮出现两条记录（复制粘贴）。预期 `sbce-duplicate-iteration`。
- **错误做法**：删除 `constraint_review`，只留各子系统的最优选择。跨子系统约束是本方法的核心检查。预期 `sbce-constraint-review-missing`。
- **错误做法**：把 `automatic_approval` 改为 `true`，理由是"证据充分"。分析结论不构成批准。预期 `fictional-approval`。

**输入不足**：`LAB-1` 明确"B 的恢复能力尚待实验"，因此第 1 轮 B 的状态只能是"保留待评"，不能预判为淘汰或选中。`LAB-2` 保留的"原始失败日志"未在本案例中展开内容，故第 2 轮 B 的淘汰理由只能引用 `LAB-2` 的结论文字，不能细化到具体的恢复时间数值。`LAB-3` 未给 C 的具体延迟数据，C 的选中依据是"契约兼容"而非性能。

## 评审记录

- 核对四个备选（A/B/C/D）各自有完整迭代序列，无备选在某轮凭空消失。
- 核对 D 在第 1 轮淘汰有直接证据（`LAB-1` 响应窗口不符）。
- 核对 B 在第 2 轮淘汰与第 4 轮重开两条记录并存，未互相覆盖。
- 核对 A 在第 2 轮选中与第 3 轮淘汰两条记录并存。
- 核对每条淘汰均带 `new_evidence_refs`，无空证据淘汰。
- 核对 `constraint_review` 存在且覆盖 A/C 与 B/C 两组跨子系统约束。
- 核对 `iteration_count=4` 与迭代序列长度一致。
- 核对 `automatic_approval=false`，全表无"已批准"表述。
- 核对修改演练中"B 变好"未推导出"A 变差"。
