# 区分人员熟练度、角色目标与团队容量

所有业务资料、人物、数值、政策及证据均为虚构教学材料；指南只提供方法依据，项目规则不冒充TOGAF规定。案例完整演练不等于独立业务评审通过。

方法：`architecture-role-skill-assessment`。当前依据：G249 §5–6；G198仅用于历史对照，量表不合并。
入口：[architecture-role-skill-assessment](../analysis-methods/architecture-role-skill-assessment.md)。

|证据 ID|原始材料|
|---|---|

|skill-4|甲本月仅有0.5全时当量可用；乙有协调技能3级与0.25全时当量。项目工作量估算尚未完成。|

## 来源规则与项目规则

1. **来源依据（G249 §5 角色与技能；§6 允许按企业裁剪）**：以角色所需技能与熟练度框架描述配置差距，技能等级用于比较角色要求与个人现状。
2. **项目测量约束（非原文逐字规则）**：等级按有序类别解释；应报告目标与现状及缺失行为，不把等级差当作等距能力缺口。
3. **项目规则**：具体角色目标（3、3、2）、证据判据与四级文字锚点，均为本案例的项目规则；材料明示不宣称为指南逐字定义。
4. **项目规则**：可用容量（全时当量）独立记录；未知工作量不得推断为配置足够。

**来源依据**：[G249 §5–6官方原文](https://pubs.opengroup.org/togaf-standard/architecture-roles-and-skills/Architecture-Roles-and-Skills.html#chap05)；[随技能包保存的四级定义与原始矩阵](../source-tables/g249-skill-proficiency.json)。本例的“独立并评审”锚点是项目细化；G249三级仍明确困难情形需要专家支持。

## 转换与推理

1. **先按锚点定现状等级，不按印象**。逐项核对 `skill-2` 是否对 `skill-3` 的锚点提供正向证据：
   - 数据建模：能独立完成两个逻辑模型**并通过评审** → 锚点 3
   - 协调：在**导师主持下完成访谈与冲突记录** → 锚点 2（有指导应用的正向证据）
   - 安全分析：仅能**按清单识别**，尚无“在指导下应用控制”的证据 → `proficiency=null`、`assessment_state=evidence_insufficient`
   
   关键判断：缺少3级证据不能反推出2级。安全分析既未证明独立完成控制，也未证明在指导下应用控制；现状保持待评估，不把未知填成1或2。

2. **现状对目标，逐项判定差距**：
   | 技能 | 角色目标 | 现状 | 判定 |
   | --- | --- | --- | --- |
   | 数据建模 | 3 | 3 | 满足 |
   | 协调 | 3 | 2 | **缺独立主持与冲突归纳证据** |
   | 安全分析 | 2 | 未评估 | **缺指导应用控制的正向证据** |

   已识别协调的行为发展需求；安全仍是评价证据缺口，不能提前断言达标或不达标。两者分别安排实践与补证。

3. **"满足本次目标"不等于"能承担该角色"**。安全分析目标为2、现状待评估；即使以后证明满足本项目目标，也不能推断具备安全架构负责角色的完整能力。因此 `ROLE-DATA` 的结论限定为"本项目角色配置"，不外推为"该员工可担任安全架构负责人"。

4. **发展动作要绑定可验证产出**。`DEV-1` 的路径是"共同主持 → 独立主持 → 依据真实产出复评"，并明确**培训出席不等于评级提升**。锚点 3 要求"独立完成并评审结果"，那么证据就必须是主持记录 + 评审人核对决策记录与异议处理，而不是听完某门课。

5. **容量与熟练度是两个维度**。`skill-4` 给甲 0.5、乙 0.25 全时当量。熟练度回答"能不能做"，容量回答"有多少时间做"。两者**不能相乘成一个"有效能力"分数**：0.5 × 3 = 1.5 这样的运算没有业务含义。

6. **工作量未知时不下"人力足够"的结论**。`skill-4` 明确"项目工作量估算尚未完成"，因此 `GAP-SKILL` 只能记"不能承诺人力足够"，而不是"人力不足"或"人力充足"。

## 四级锚点的判据

锚点是判定的标尺，每一级必须有可观察的行为差异：

| 级 | 定义 | 可观察的判据 | 本案实例 |
| --- | --- | --- | --- |
| 1 | 能在指导下识别概念 | 说出术语但无法应用 | — |
| 2 | 能在指导下应用 | 应用时需他人主持或核对 | 协调（在导师主持下完成访谈和记录） |
| 3 | 能独立完成并评审结果 | 独立产出且结果经他人评审通过 | 数据建模（两个模型通过评审） |
| 4 | 能指导他人及改进方法 | 教会他人且改进方法本身 | — |

**本项目锚点以“独立并评审”区分2与3；不冒充G249逐字定义。** 安全仅能按清单识别，不足以证明本项目2级的指导应用能力，因此保持证据不足；需要观察实际控制方案及专家指导记录。

**"评审结果"是 3 的必要条件**。自己完成但无人评审，只能说 3 未获证实；能否记 2 仍须对应的指导应用证据，不能把缺评审直接降成 2。评审记录是这类判定的关键证据。

## 三个维度的分离

角色配置有三个可独立变化的维度，混在一起判断会产生错误结论：

| 维度 | 回答什么 | 本案数据 | 独立性 |
| --- | --- | --- | --- |
| 技能等级 | 已证明能做到什么 | 3 / 2 / 未评估 | 与容量无关 |
| 可用容量 | 有多少时间做 | 甲 0.5、乙 0.25 | 与等级无关 |
| 角色目标 | 该角色要求多高 | 3 / 3 / 2 | 与个人现状无关 |

**三者不可相乘或相除**。"0.5 全时当量 × 3 级 = 1.5 有效能力"这类运算没有业务含义——等级是序数，不能与容量做乘法。

**"满足目标"与"能承担该角色"也不同**。安全分析目标为2、现状待评估；即使以后证明满足本项目目标，也不能推断具备安全架构负责角色的完整能力。因此 `ROLE-DATA` 的结论限定为"本项目角色配置"。

## 发展动作的设计

| 要素 | 要求 | 本案实例 |
| --- | --- | --- |
| 起点 | 当前等级与缺口行为 | 协调2（已在导师主持下完成访谈与记录） |
| 路径 | 递进的可观察台阶 | 共同主持 → 独立主持 |
| 证据 | 完成后能出示什么 | 主持记录 + 评审人核对决策与异议处理 |
| 复评 | 谁在何时判定 | 评审人依真实产出复评 |

**培训出席不能替代证据**。锚点 3 要求"独立完成并评审结果"，证据必须是产出与评审，不是"听完了某课程"。

## 修改演练

**情景一：甲完成独立主持但未留异议处理记录**。这次3级复评证据不足；历史已获正向证据支持的2级记录保留，不把本次未知重新判作2。`DEV-1`不完成，另记协调复评证据缺口；安全`GAP-EVID`独立保留。

**情景二：甲经评审完整达到锚点 3**。新增协调3级观察，`DEV-1`标记完成、协调复评证据缺口关闭；安全`GAP-EVID`不受影响。**目标值保持 3 不变**，历史证据（评审记录与日期）随现状更新一并保留，不覆盖旧记录。

**情景三：乙的 0.25 当量被误当作"能力不足"**。这是把容量维度混入熟练度维度。乙协调 3 级已达标，限制在可用时间而非能力。正确处置是补任务估算后判断是否追加投入，而非降低其技能评级。

**影响范围**：情景一、二影响 `ROLE-DATA` 的协调项与 `DEV-1` 状态；情景三影响 `GAP-SKILL` 的表述与人力计划，不影响技能评级。

## 反例与输入不足

- **错误做法**：把三个技能等级平均得 2.33 并称其为组织成熟度。平均值不是成熟度。预期 `unsourced-maturity-rating`。
- **错误做法**：把"同为 3 级"当作可等价交付，忽略 0.1 与 1.0 全时当量的差别。等级相同不等于当量相同。预期 `measurement-basis-gap`。
- **错误做法**：以证书名称替代本项目要求的行为证据。证书不是行为证据。预期 `missing-evidence`。
- **错误做法**：安全项缺证据仍判2级达标，进而推断该员工可担任安全架构负责人。本项目目标不等于该角色的一般要求。预期 `unsourced-maturity-rating`。
- **错误做法**：因甲参加过协调培训，就把协调从 2 升为 3。锚点 3 要求独立完成并评审结果。预期 `missing-evidence`。
- **错误做法**：把 0.5 全时当量乘技能等级 3 得"1.5 有效能力"再与他人比较。两个维度不可相乘。预期 `measurement-basis-gap`。

**输入不足**：项目工作量估算尚未完成，因此本案例不判断人力是否充足。安全分析缺指导应用控制的直接记录，`GAP-EVID`因此保留未决；协调的独立主持及评审证据仍是发展验收条件。

## 评审记录

- 核对锚点与证据逐项对应：每个等级判定都能指回 `skill-2` 的具体行为描述。
- 核对目标由角色需求给出（`skill-1` 的 3、3、2），非由个人现状倒推。
- 核对容量与熟练度分栏记录，未相乘、未互相折算。
- 核对协调2级有指导应用的正向证据，安全证据不足不自动评级；发展需求与证据缺口分开。
- 核对发展动作绑定可验证产出与独立复评条件，未以培训出席替代。
- 核对"满足本项目目标"与"可承担该角色"被显式区分。
- 核对等级为序数，未把 3−2 解释为等距缺口。
- 核对三项修改情景分别说明哪些字段变、哪些不变。
