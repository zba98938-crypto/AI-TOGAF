# 数字使能胜任力映射：DPBoK 语境不是成熟度等级

## 决策与原始业务资料

项目团队分布在四个 DPBoK 语境，各语境需要什么胜任力？

| 证据 ID | 原始材料 |
|---|---|
| `R06` | 产品负责人 `P-OWNER` 有访谈/用例和待办；信息管家 `DATA-STEWARD` 维护字段字典但保留规则未定；架构顾问 `EA-LEAD` 有草案但组合排序未定；安全负责人 `SEC-LEAD` 有授权草案但缺演练。 |

| `R04` | 能力是受理与核验，不等于参考功能名。 |

## 来源规则与项目规则

1. 来源方法（G21H）：DPBoK 的四个语境（个人、团队、团队之团队、持久企业）描述**组织规模化程度**，不是成熟度等级。
2. 来源方法：胜任力映射需把角色与具体能力要求关联，不能只列角色名。
3. 项目规则：**语境不是等级**（`R06`/`R07`）；不得把"团队之团队"读作比"团队"更成熟。
4. 项目规则：每个角色的胜任力判定必须有证据；草案、未定、待确认可证明工作存在，但不能证明胜任力完整具备。

## 转换与推理

1. **角色分语境**：

| 语境 | 角色 | 现有证据 | 胜任力判定 |
| --- | --- | --- | --- |
| 团队 | `P-OWNER` | 访谈、用例、待办 | 具备（产品侧） |
| 团队 | `DATA-STEWARD` | 字段字典，保留规则未定 | 部分 |
| 团队之团队 | `EA-LEAD` | 草案，排序未定 | 部分 |
| 团队之团队 | `COORD` | 交接会议 | 具备（协调） |
| 团队 | `TEAM-LEAD` | 协作值班表 | 具备（协作） |
| 团队 | `OPS` | 轮值，未做恢复演练 | 部分 |
| 团队之团队 | `PLATFORM` | 试验环境，生产权限待确认 | 部分 |
| 团队之团队 | `SEC-LEAD` | 授权草案，缺演练 | 部分 |
| 团队 | `DELIVERY` | 待办与构建草案 | 部分 |
| 团队之团队 | `PROCUREMENT` | 清单未估算 | 部分 |

2. **不排等级**：上表按语境分组，不按"成熟度从低到高"排列。语境是组织规模，不是能力高低。
3. **胜任力不等于头衔**：`R04` 的原则同样适用——有角色名不等于具备对应胜任力，必须看证据。
4. **缺口导向**：7 个"部分"角色各自的缺口不同（缺演练、缺估算、缺排序），需分别补，不能统一"加强培训"。

5. **语境是组织规模，不是能力高低**。四个 DPBoK 语境描述"覆盖范围有多大"，不描述"做得有多好"：

| 语境 | 覆盖范围 | 不表示 |
| --- | --- | --- |
| 个人 | 一人承担 | 能力弱 |
| 团队 | 一个交付团队 | 比个人成熟 |
| 团队之团队 | 多团队协调 | 比团队成熟 |
| 持久企业 | 组织级持续 | 最高级 |

   把语境当等级，会导致"在团队之团队的角色一定比团队的角色强"这类错误排序。本案 `TEAM-LEAD`（团队语境）与 `SEC-LEAD`（团队之团队语境）的胜任力判定均为"具备/部分"，与语境无关。

6. **胜任力判定的三档口径**：

| 判定 | 判据 | 本案实例 |
| --- | --- | --- |
| 具备 | 有完整可用的产出证据 | `P-OWNER`（访谈+用例+待办） |
| 部分 | 有基础但关键环节缺失 | `DATA-STEWARD`（字典有，保留规则未定） |
| 未知 | 无证据，不能反推不具备 | 本案无此类 |

   **"草案""未定""待确认"一律不构成"具备"的证据**——这是项目规则的直接要求。

7. **"部分"必须具体化到缺什么**。7 个"部分"角色各自的缺口不同：

   | 角色 | 缺什么 |
   | --- | --- |
   | `DATA-STEWARD` | 保留规则未定 |
   | `EA-LEAD` | 组合排序未定 |
   | `OPS` | 未做中断恢复演练 |
   | `PLATFORM` | 生产发布权限未确认 |
   | `SEC-LEAD` | 缺演练 |
   | `DELIVERY` | 构建草案 |
   | `PROCUREMENT` | 清单未估算 |

   把这些统一归因于"需要加强培训"，会掩盖七种完全不同的缺口——有的是缺决策，有的是缺演练，有的是缺估算。

8. **角色名不等于胜任力**。`R04` 的原则在此同样适用：有 `SEC-LEAD` 这个头衔，不等于具备安全领导胜任力（缺演练）；有 `PROCUREMENT` 这个职能，不等于具备寻源胜任力（未估算）。

## 修改演练

**情景一：`OPS` 完成一次中断恢复演练并留记录**。`COM-1` 中 `OPS` 从"部分"转"**具备**"，仅限运维恢复这一项胜任力——**不影响该角色的其他能力，也不影响其他角色**。

**情景二：某角色从"团队"调到"团队之团队"**。语境变化**不代表胜任力提升**。需按新语境的证据要求重新判定：多团队协调所需的证据与单团队不同。

**情景三：`DATA-STEWARD` 的保留规则确定**。从"部分"转"具备"，`COM-3` 的缺口清单减一项。但需确认规则**已发布并被使用**，不只是"定下来了"。

**情景四：业务方要求"给团队一个整体胜任力评分"**。10 个角色的判定不可加总为团队分数——**不同角色的胜任力不是同一尺度的分量**，且语境不同。可行做法是保留分角色的判定清单。

**影响范围**：情景一、三改变单个角色判定；情景二重置评估基准；情景四涉及尺度合并。四种情形下"语境不是等级"的规则不变。

## 反例与输入不足

- **错误做法**：给四个语境打成熟度分（个人 1 级、团队 2 级……）。语境不是等级。预期 `unsourced-maturity-rating`。
- **错误做法**：因某角色有头衔即判胜任力具备。头衔不构成证据。预期 `missing-evidence`。
- **错误做法**：把 7 个"部分"统一记为"需培训"。缺口各异，笼统归因无法行动。预期 `missing-evidence`。
- **输入不足**：`COM-GAP-1`、`COM-GAP-2` 两项证据缺失。
