# 工作包优先级判定：权重有来源才出总分，敏感区间必须一起交

虚构集团要在三个工作包里定顺序：主数据治理、报表平台替换、结算系统重构。权益、风险降低、成本三条准则，权重 0.4/0.4/0.2，来源是董事会 2026-09 决议。本案例演练：权重来源如何校验、成本为何要先转换、为什么敏感度分析不是可选项。

所有业务材料、评分、权重与决议均为虚构教学材料。**权重来源"董事会 2026-09 决议"是本例唯一来源，不是 TOGAF 默认权重。**

方法：`work-package-prioritization`。来源方法：G186 §8.4、G176 §12.8。
入口：[work-package-prioritization](../analysis-methods/work-package-prioritization.md)。

## 决策与原始业务资料

要回答：**这三个工作包该按什么顺序做？这个顺序稳不稳？**

| 证据 ID | 原始材料 |
|---|---|
| `WPK-1` | `W-A` 主数据治理：收益**高**、风险降低**中**、成本 **80 万**。 |
| `WPK-2` | `W-B` 报表平台替换：收益**中**、风险降低**低**、成本 **40 万**。 |
| `WPK-3` | `W-C` 结算系统重构：收益**高**、风险降低**高**、成本 **150 万**。 |
| `WPK-4` | 准则与权重：收益 **0.4**、风险降低 **0.4**、成本 **0.2**。 |
| `WPK-5` | **权重来源**：董事会 2026-09 决议"本期优先降风险与提收益，成本次之"。**该决议为唯一来源。** |

## 来源规则与项目规则

1. **来源方法（G186 §8.4、G176 §12.8）**：**每条权重必须有来源**（裁决记录、政策、历史基准）；缺来源的权重标记为无效。
2. **来源方法**：**只要存在无效权重，不计算总分**，输出准则清单与待补来源。
3. **来源方法**：权重齐备时按准则评分，**每条评分记录证据**。
4. **来源方法**：对权重做**敏感度检查**——单条权重 ±20% 时排序是否翻转，输出敏感区间。
5. **项目规则**：成本是**逆向指标**（越低越好），须显式声明转换规则后才能纳入加权。
6. **项目规则**：权重之和须为 1.0；不等于 1.0 时不得直接加权。
7. **项目规则**：排序结果**不等于授权**；本方法不给工作包批准状态。

## 转换与推理

1. **先校验权重来源（第 1 步）**。三条权重 0.4/0.4/0.2 均可追溯到 `WPK-5` 的同一句决议 ⇒ `invalid_weights=[]`。**这一步是闸门**：若决议只提"重收益"而未提风险，则风险权重无来源，必须停下来只列准则。

2. **成本转换必须显式声明**。成本越低越好，不能直接加权。本案例规则：以预算上限 150 万为基准，`成本得分 = 1 − 成本/150`，再乘 5 得到 **0–5** 成本偏好量表（不是 1–5）。
   - `W-A`：(1 − 80/150) × 5 = **2.3333**
   - `W-B`：(1 − 40/150) × 5 = **3.6667**
   - `W-C`：(1 − 150/150) × 5 = **0.00**
   
   转换规则写进输出，因为**换一个基准（如 200 万）分数会变，排序可能变**。

3. **评分与加权（第 3、4 步）**：下表收益/风险分数是缺锚点条件下的候选输入，仅用于算术演练，不是已证实可比的决策分数；正式排名须先确认量表。
| 工作包 | 收益 | 风险降低 | 成本得分 | 加权总分 |
|---|---|---|---|---|
| `W-A` | 4 | 3 | 2.3333 | 0.4×4 + 0.4×3 + 0.2×2.3333 = **3.2667** |
| `W-B` | 3 | 2 | 3.6667 | 0.4×3 + 0.4×2 + 0.2×3.6667 = **2.7333** |
| `W-C` | 4 | 5 | 0.0000 | 0.4×4 + 0.4×5 + 0.2×0.0000 = **3.6000** |
   
   排序：**W-C > W-A > W-B**。

4. **敏感度（第 5 步）**：先按逐项权重相对 ±20%、其余不变后归一化检查六个端点，仍为 W-C > W-A > W-B。这只是局部稳定性。再作更大的联合情景：把风险权重从 0.4 降到 0.2（收益 0.5、成本 0.3），并非单项 ±20%：
   - `W-A`：0.5×4 + 0.2×3 + 0.3×2.3333 = 2.0 + 0.6 + 0.700 = **3.300**
   - `W-C`：0.5×4 + 0.2×5 + 0.3×0 = 2.0 + 1.0 + 0 = **3.00**
   - **`W-A` 反超 `W-C`，排序翻转。**
   
   进一步精确定位翻转点：在收益权重 = 0.8 − 风险权重、成本权重固定 0.2 的条件下，两式之差为 `0.2 × 2.3333 − 2 × 风险权重`，令其为 0 得 **风险权重 = 0.2333**。因此风险权重 **< 0.2333** 时 `W-A` 反超 `W-C`；风险权重 0.24 时 `W-C` 仍以 3.44 对 3.4267 领先。结论必须写成"在既定权重 0.4/0.4/0.2 下 W-C 优先；**但排序对风险权重敏感，翻转阈值为 0.2333**"。

5. **为什么敏感度不能省**。若只报"W-C 第一"，董事会会以为结论稳健。实际上在成本权重固定 0.2、收益权重=0.8−风险权重的扫描路径下，风险权重低于精确阈值 7/30（约 0.2333）才换第一；0.3 时仍是 W-C 第一。**不报敏感区间的排序，是把一个条件结论伪装成无条件结论。**

6. **成本得分的极端值**。`W-C` 成本等于预算上限 ⇒ 得分 0.00。若预算上限设为 200 万，`W-C` 得分 = (1 − 150/200) × 5 = 1.25，总分变为 3.85，与 `W-A` 拉开。**基准选择直接影响排序**，因此转换规则必须与结论同屏呈现。

## 修改演练

改动一处输入：成本权重从 0.2 提到 0.35（收益 0.3、风险 0.35）。

- `W-B`：0.3×3 + 0.35×2 + 0.35×3.6667 = 0.9 + 0.7 + 1.283 = **2.883**
- `W-A`：0.3×4 + 0.35×3 + 0.35×2.3333 = 1.2 + 1.05 + 0.817 = **3.067**
- `W-C`：0.3×4 + 0.35×5 + 0.35×0 = 1.2 + 1.75 + 0 = **2.950**
- 新排序：**W-A > W-C > W-B**。`W-B` 仍为第三，`W-A` 从第二升至第一，`W-C` 从第一降至第二。
- 影响：`portfolio-estimate-sufficiency-check` 的结论、`implementation-migration-plan` 的批次顺序。
- **权重变更必须有新来源**。若董事会未出新决议，这组新权重即为无效，`invalid_weights` 非空，**不得提交正式总分**；上列仅为明确假设下的敏感性演练。

反向演练：若另有新决议明确采用收益 0、风险 0.7、成本 0.3（仅说"只重降风险"并不足以支持成本 0.3）：
- `W-A`：0.7×3 + 0.3×2.3333 = 2.1 + 0.700 = **2.800**
- `W-C`：0.7×5 + 0.3×0 = **3.50**
- `W-B`：0.7×2 + 0.3×3.6667 = 1.4 + 1.100 = **2.500**
- 排序仍 W-C > W-A > W-B，W-C 与 W-A 的候选分差扩大为 0.7，但不能说敏感区间消失。沿收益=0、成本=1−风险的路径，W-C 与 W-A 仍在风险权重 7/13（约 0.5385）相等；集中权重不普遍保证稳定。

## 反例与输入不足

- **错误做法**：五项准则各给 20% 权重，但无任何来源或裁决记录。权重不承载任何已说明的偏好。预期 `missing-evidence`。正确处置：`invalid_weights` 非空时不计算总分，只列准则与候选。
- **错误做法**：成本直接按"150 万 = 5 分、40 万 = 1 分"反向线性缩放但不声明规则。转换规则未声明。预期 `measurement-basis-gap`。
- **错误做法**：权重之和为 1.2 仍直接加权，总分量级被放大。预期 `measurement-basis-gap`。
- **错误做法**：只报"W-C 第一"，不报敏感区间。条件结论被伪装成无条件结论。预期 `missing-evidence`。
- **错误做法**：给 `W-C` 评分 5 分但无任何证据（评审记录、技术评估）。评分须有证据。预期 `measurement-evidence-gap`。
- **错误做法**：输出排序后声明"因此批准 W-C 立项"。排序不是授权。预期 `approval-without-evidence`。
- **错误做法**：把三个工作包的"高/中/低"直接当 3/2/1 用，未与 1–5 量表对齐。量表不一致。预期 `measurement-basis-gap`。

**输入不足**：`WPK-1`–`WPK-3` 只给"高/中/低"定性档，**未给 1–5 量表的锚点定义**（`WPK-GAP-1`），因此本案例的评分 4/3/4 等是按常识映射，必须标注为待确认。成本换算基准 150 万的来源未说明（`WPK-GAP-2`）——它恰好等于 `W-C` 的成本，可能是巧合也可能是有意设定，材料未言明。**这两项缺口意味着总分虽有算术正确性，但量纲与锚点仍需业务确认。**
