# 业务属性画像：99.6% 还是 99.2% 取决于分子怎么算

虚构市民图书馆要衡量"预约变更可追责"这一业务属性。2026 年 9 月抽样 1,000 条预约变更，996 条同时具备不可改写的操作者标识与时间戳，达标率 99.6%。但复核发现其中 4 条标识来自共享账号、不能归属个人，有效记录降为 992 条，比率变为 99.2%——**从达标变成必须纠偏**。本案例演练业务属性如何定义口径、如何处理容差边界、以及为什么空样本不能算成 100%。

所有业务材料、人物、抽样与规则均为虚构教学材料（`B-R1`–`B-R4`）。**99.5% 目标、0.2 个百分点容差、99.3% 触发线均为本例项目规则，不是 TOGAF 默认值。**

方法：`business-attribute-evaluation`。来源方法：G152 §5.10.1；English PDF 40–41。
入口：[business-attribute-evaluation](../analysis-methods/business-attribute-evaluation.md)。
素材：案例（历史材料已清理）、基线结果（历史材料已清理）。

## 决策与原始业务资料

要回答：**这个业务属性到底达没达标？差多少？谁该动手？**

| 证据 ID | 原始材料 |
|---|---|
| `B-R1` | 馆长：座位被取消后必须能找到操作者。保留原记录，后续修正不能覆盖最初记录。 |
| `B-R2` | 案例治理小组规则：每月抽样预约变更记录，操作者与时间均可追溯的比例目标**至少 99.5%**；**最多容忍比目标低 0.2 个百分点**，**低于 99.3% 时由服务台负责人发起纠偏**。该属性**不使用损失金额阈值**。 |
| `B-R3` | 2026 年 9 月抽样 1,000 条，有 **996 条**同时具备不可改写的操作者标识和时间戳。**抽样只覆盖预约变更，不包括浏览日志。** |
| `B-R4` | 复核发现 **4 条标识来自共享账号，不能归属个人**。有效记录从 996 改为 **992**；总样本仍 1,000。 |

## 来源规则与项目规则

1. **来源方法（G152 §5.10.1）**：业务属性应被定义为**可观察、可度量**的业务状态，含明确范围、度量口径、目标与责任主体。
2. **来源方法**：属性须区分"业务定义"与"度量口径"——前者说是什么，后者说怎么算。
3. **项目规则（`B-R2`）**：目标 `>= 99.5%`；容差 `0.2 percentage-point`，方向 `below-target`；纠偏触发 `< 99.3%`，运算符**严格小于**。
4. **项目规则**：容差单位是**百分点（percentage-point）**，**不是**相对百分比。0.2 个百分点 ≠ 目标的 0.2%。
5. **项目规则**：**不使用损失金额阈值**（`B-R2` 明示）。本属性不折算成金额。
6. **项目规则**：`frequency_or_cost_threshold` 标 `not-applicable` 并附理由，但 `review_cadence` 仍需写 `monthly`。

## 转换与推理

1. **先定业务定义，再定口径**。`definition` 写"在月度抽样的预约变更范围内，每条操作均可追溯到唯一个人和不可改写的时间戳"。注意两个限制词：**月度抽样**（不是全量）、**预约变更**（不含浏览日志，`B-R3` 明示）。

2. **分子规则与分母规则分开写**。`numerator_rule`："个人操作者和时间戳**同时**有效"——是**并且**，不是"或"。`denominator_rule`："样本中所有预约变更记录"。这个"并且"是 `B-R4` 能推翻结论的原因：共享账号有时间戳但**不能归属个人**，因此不满足"并且"。

3. **基线计算（可复核的算术）**：`100 × 996 / 1000 = 99.6`。与目标 99.5 比较，`target_gap = 99.6 - 99.5 = +0.1`，`status = meets-target`，`corrective_action = false`。这一步是纯算术，任何人用同样输入都能得同结果。

4. **容差语义必须钉死**。`tolerable_deviation = {value: 0.2, unit: "percentage-point", direction: "below-target"}`。容许下限 = 99.5 − 0.2 = **99.3**。`corrective_action_trigger = {operator: "<", threshold: 99.3}`。**严格小于**意味着 99.3 恰好不触发——这是边界行为，必须由规则给出，不能凭直觉。

5. **修改后重算**：`B-R4` 把分子从 996 改为 992。`100 × 992 / 1000 = 99.2`。`target_gap = 99.2 - 99.5 = -0.3`。99.2 < 99.3 ⇒ `status = corrective-action-required`，`corrective_action = true`，动作方为服务台负责人并复核共享账号。

6. **边界测试**：99.3 时 `status = within-tolerance`、`corrective_action = false`。这条测试的价值在于：如果实现把 `<` 写成 `<=`，99.3 会被误判为纠偏，而实际上它"刚好在容差内"。案例显式声明这一点，是为了让规则可被反例检验。

7. **不使用金额阈值**。`frequency_or_cost_threshold` 写 `{status: "not-applicable", reason: "此属性按样本可追溯比例评判；案例未采用事件发生频率或损失金额阈值", review_cadence: "monthly"}`。**标 not-applicable 不等于省略**——理由与复查频率仍需给出。

## 判定规则的结构

属性画像有五个彼此独立的要素，缺一即无法判定：

| 要素 | 作用 | 本案取值 |
| --- | --- | --- |
| 目标 | 应达到的水平 | `>= 99.5%` |
| 容差 | 容许偏离目标多少 | `0.2` 百分点，方向低于目标 |
| 临界值 | 触发纠偏的下限 | `99.3%` |
| 触发运算符 | 临界值处如何判 | `<`（严格小于） |
| 纠偏动作与责任方 | 触发后谁做什么 | 服务台负责人复核共享账号 |

**容差与临界值必须一致**：`99.5 − 0.2 = 99.3`。若两者不一致（如容差 0.2 但临界值写 99.0），则规则自相矛盾，判定结果取决于用哪个数。

**运算符的边界语义**：

| 观测值 | 判定 | 理由 |
| --- | --- | --- |
| 99.6% | 达标 | ≥ 目标 |
| 99.4% | 容差内 | < 目标但在 99.3 之上 |
| 99.3% | 容差内 | **恰在临界值，`<` 不成立** |
| 99.29% | 需纠偏 | < 99.3 |

第 3 行是最容易出错的位置：若实现把 `<` 写成 `<=`，99.3% 会被误判为需纠偏。

**分子的"并且"语义**。分子规则是"个人操作者**和**时间戳同时有效"。因此共享账号记录（有时间戳但不能归属个人）**不满足**分子条件。若把"并且"读成"或"，分子会虚高。

## 修改演练

改动一处输入：`B-R4` 的共享账号从 4 条增至 8 条（有效记录 996 → 988）。

- `metric.numerator`：996 → 988；`denominator` 仍 1,000。
- `observed`：`100 × 988 / 1000 = 98.8`。
- `target_gap`：`98.8 - 99.5 = -0.7`。
- `status`：`corrective-action-required`（98.8 < 99.3）。
- `corrective_action`：`true`。
- 影响：`baseline-result` 的观测值、差距、状态三字段变化；`target`、`tolerable_deviation`、`corrective_action_trigger` **全部不变**——规则不因观测变差而放宽，这正是属性画像的价值。
- 若同时有人主张"把目标降到 98.5% 就不用纠偏了"，这属于**变更项目规则**，必须作为独立变更记录并说明依据，不能在同一个 `modification` 里偷偷改 `target.value`。

反向演练：若 `B-R3` 的样本从 1,000 改为 100（99 条有效），观测变为 99.0%；这不是原 996/1000 的同比例样本。但此时**不能宣称"与 1,000 样本等价"**——样本量差异影响结论稳定性，`sampling` 字段必须同步声明"样本 100 条，不外推全体"。

## 反例与输入不足

- **错误做法**：删除 `tolerable_deviation`，实现时按 0 容差处理（即 `< 99.5%` 就纠偏）。容差不能被默认推断。预期 `BAP-002`。
- **错误做法**：把 `tolerable_deviation.unit` 改为 `percent-of-target`，阈值仍是 99.3%。0.2% 相对变化 ≈ 0.199 个百分点，与 0.2 个百分点不等价。预期 `BAP-003`。
- **错误做法**：`metric.denominator = 0` 时输出 100%。空样本不能算成满分。预期 `BAP-001`。
- **错误做法**：把共享账号的记录计为"有效"，理由是有时间戳。分子规则要求"并且"，共享账号不满足个人归属。预期 `measurement-basis-gap`。
- **错误做法**：把 4 条共享账号记录从样本中删除，分子仍为 992、分母改为 996，得约 99.5984%，虚增并翻为达标；不是 100%。**删除不合格样本会虚增比率**。预期 `measurement-basis-gap`。
- **错误做法**：把该属性折算为"每年约损失 12 万元"。`B-R2` 明示不使用损失金额阈值。预期 `measurement-basis-gap`。

**输入不足**：`B-R3` 只覆盖 2026 年 9 月单月，未给历史序列，因此**不能判断趋势**。`B-R4` 未说明共享账号的使用者范围与责任人，只能记为待整改项。`B-R2` 未定义"不可改写"的技术验证方式（是审计日志、哈希链还是权限控制），故度量口径中该项保持为"不可改写的操作者标识和时间戳"，不细化到具体机制。

## 评审记录

- 核对业务定义含范围限制（月度抽样、仅预约变更），未泛化为"安全性"。
- 核对分子规则为"并且"关系，基线 996 与修改后 992 的差异可追到该逻辑。
- 核对分母在修改中保持 1,000，未通过删样本虚增比率。
- 核对容差单位为 percentage-point，且容许下限 99.3 与触发线一致。
- 核对触发运算符为严格小于，边界 99.3 的判定被显式测试。
- 核对 `frequency_or_cost_threshold` 标 not-applicable 但附理由与复查频率。
- 核对修改中规则字段（target / tolerance / trigger）未被同步放宽。
- 核对单月样本未被外推为全年结论。
