## 决策与原始业务资料

核查年度环境变化并为架构方案提供有单位、范围及计算依据的数据。

|证据 ID|原始材料|
|---|---|
|env-meter|虚构试点电表：新增服务2026年用电172.5kWh；同边界退役设备基线对应1150kWh/年。服务量假设相同，退役量只是项目反事实比较，并非现金或实际负排放。|
|env-rule|本例采用的虚构核算系数0.4kgCO2e/kWh；项目规则为同期间同边界新增减退役。Scope 2运营电力与Scope 3制造分列，不自动相加，抵消另记。该系数不是TOGAF或真实地区排放因子。|

|env-meter-new|v2校准后新增服务用电215kWh，对应新增86kgCO2e；同边界退役仍460，项目新报告净值−374。|

## 来源规则与项目规则

1. **来源方法**：环境核算以业务/信息系统评估、生命周期边界与方案变化为基础；具体因子、分摊方式与算术规则都必须有依据。
2. **来源方法**：历史制造排放属于已发生事实，不因设备退役而从本期抹去；跨 Scope 不得直接相加。
3. **项目规则**：本例的 0.4 系数与"相同服务量"前提是**虚构项目假设**，不是来源给的默认值。
4. **项目规则**：计算器只执行已审查的新增/退役数值差，**不从原始设备信息自动推断排放**；边界或因子未声明时不给总量。

**来源依据**：`references/capability-addenda/environment-lifecycle-accounting.md`。

## 转换与推理

1. 先整理活动数据：172.5kWh×0.4kgCO2e/kWh=69kgCO2e；1150×0.4=460kgCO2e。记录期间、服务量假设、系数和来源；未把kWh与kgCO2e直接相加。
2. 将两行已审查结果交给environmental-delta：运营69−460=−391；制造120−0=120。计算器不跨行输出总量。
3. 原报表−390与算术−391差1，输出reported_net与calculated_net及待核查项；不静默改原值，也不把差异当作新的公式。
4. 列出未决：服务量是否真实可比、退役是否实施、供应商制造边界是否一致。项目决策不能把全部计算值视为已实现减排。

5. **单位不同是硬边界，不是格式问题**。活动数据是 kWh，结果是 kgCO2e。两者之间只有**乘以排放因子**这一条合法通道：
   - 172.5 kWh × 0.4 kgCO2e/kWh = 69 kgCO2e ✓
   - 172.5 + 69 = 241.5 ✗（单位不同不能相加）

   跨单位相加是最容易被忽略的错误，因为它"算得出来"。

6. **Scope 2 与 Scope 3 分列，不自动相加**。`env-rule` 明确运营电力（Scope 2）与制造（Scope 3）分列。理由：
   - 边界不同（运营发生在使用期，制造发生在生产期）
   - 时间归属不同（本期用电 vs 本期新增设备的一次性制造）
   
   相加需要**额外的约定期限规则**，材料未给。

7. **"退役量"是反事实比较，不是负排放**。`env-meter` 明确退役 1150kWh/年 只是项目反事实比较，**不是现金节省，也不是实际负排放**。
   - 说"减少 460 kgCO2e"意味着：若设备继续运行会产生这些排放
   - 不能说"我们产生了 −460 kgCO2e"——本案没有移除或封存证据，不能声称产生负排放；真实碳移除可构成负排放，不能一概否认

8. **原报表 −390 与算术 −391 的 1 差异必须保留**。`env-report` 印的是 −390，复算是 −391。处置要点：
   - 输出 `reported_net` 与 `calculated_net` 两个字段
   - 标为待核查项
   - **不静默改原值**（会丢失来源冲突）
   - **不把差异当作新公式**（1 kg 的差可能是四舍五入，也可能是口径不同）

9. **计算器只做已审查数值差**。项目规则明确：计算器执行"已审查的新增/退役数值差"，**不从原始设备信息自动推断排放**。这意味着活动数据（kWh）与系数必须由人给定并审查，kWh 乘因子的换算在上游完成，environmental-delta 只负责已给排放量的减法。

10. **v2 校准的处理**。`env-meter-new` 说新增用电从 172.5 改 215 kWh，对应 86 kgCO2e，新报告净值 −374 且一致。此时：
    - 该行的算术差异告警**消除**（报告与计算一致）
    - **旧版本冲突证据仍保留**（`env-report` 的 −390 与 −391 是历史事实）

## 修改演练

**情景一：v2 将新增活动数据改为 215 kWh**。显式重算为 86 kgCO2e；计算器输出 86 − 460 = **−374**，且新报告与该值一致，该行的算术差异告警消除。**旧版本的 −390/−391 冲突证据仍在**——它们记录的是历史事实，不因新版本正确而消失。

**情景二：排放因子从 0.4 改为 0.35**。同一运营活动数据的 kgCO2e 换算结果按比例变化（制造120不依赖电力因子，保持不变）（69 → 60.4，460 → 402.5，净值 −342.1）。**但历史报告值不变**——因子变更须留版本，否则同一份报表在不同时间复算会得到不同数字而无从解释。

**情景三：退役设备实际继续运行**。此时"退役 460"不成立，运营净值回到 +69（新增用电无退役抵消）。**这是反事实假设失效，不是计算错误**——`GAP-ENV` 的"退役是否实施"正是为此。

**情景四：要求给出"总体减排 X 吨"**。需先决定 Scope 2 与 Scope 3 是否相加、按几年计、抵消如何处理。三者任一未定，总量即无定义。

**影响范围**：情景一改变单行数值与告警状态；情景二只改变用该因子的运营数值，制造不变且保留历史；情景三使反事实失效；情景四涉及边界与期限规则。四种情形下"历史制造不扣减"的规则不变。

## 反例与输入不足

- **错误做法**：去掉 `method_evidence` 后仍要求给出年度环境总量。实际计算失败。预期 `measurement-basis-gap`（缺方法依据即无总量）。
- **错误做法**：跨 Scope 相加，或把制造与运营直接求和。两类边界不同，须另有明确方法。预期 `core-vocabulary-override`（把不同边界当作同一口径）。
- **错误做法**：把已发生的历史制造排放从本期抹去，理由是"设备本来就要退役"。历史排放不因退役消失。预期 `measurement-basis-gap`。
- **错误做法**：把 172.5 kWh 与 69 kgCO2e 相加得 241.5。单位不同，只能通过排放因子换算。预期 `measurement-basis-gap`。
- **错误做法**：把退役量说成"产生 −460 kgCO2e"。反事实比较不等于负排放。预期 `measurement-basis-gap`。
- **错误做法**：静默把报表 −390 改成 −391 使二者一致。来源冲突须保留并单列待核查项。预期 `measurement-basis-gap`。
- **错误做法**：把 −390 与 −391 的 1 kg 差异当作"发现新公式"并改写核算规则。差异可能是舍入或口径，须先核查。预期 `missing-evidence`。
- **错误做法**：把 Scope 2 运营净值与 Scope 3 制造新增相加，报"总变化 −271"。跨 Scope 相加需另约定期限与边界规则。预期 `core-vocabulary-override`。
- **错误做法**：因子从 0.4 改为 0.35 后重算历史报表数值。历史报表须保留原值，变更留版本。预期 `measurement-basis-gap`。

**输入不足**：材料未给排放因子的版本与来源年份，本案例的数值只能作演示，不可用于对外披露。
