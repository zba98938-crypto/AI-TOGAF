# 四模式选择与周期切换：四种图是备选，不是四级成熟度

虚构的云港城市图书馆要上线座位预约与无障碍协助。团队在四种敏捷协作模式之间选择：仅 EA、三独立团队、混合跨职能、解决方案协作。本案例演练如何基于**容量与能力事实**选一种（而不是选最高级），以及周期切换时如何保留旧冲刺历史。

所有业务材料、人物与授权均为虚构教学材料（`R01`–`R08`）。**四种模式是互斥备选，不是成熟度 1/2/3/4 级，也不是同时部署的四个阶段。**

方法：`agile-collaboration-selection-switch`。来源方法：G210 §3.3–3.3.8。
入口：[agile-collaboration-selection-switch](../analysis-methods/agile-collaboration-selection-switch.md)。
素材：原料（历史材料已清理）、分析（历史材料已清理）、负例（历史材料已清理）。

## 决策与原始业务资料

要回答：**这一周期该用哪种模式？下周期要不要切换？切换时旧记录怎么办？**

| `R02` | **EA-T 能滚动形成能力、信息、接口与安全切片**；**DEV-A/DEV-B 能双周交付演示**。每周有支持会，EA 与开发职责分立。 |

## 来源规则与项目规则

1. **来源方法（G210 §3.3–3.3.8）**：四种模式是**互斥备选**，各有其适用条件；不存在"更高级"的模式。
2. **来源方法**：模式选择依据是**容量、能力、交接需要**等事实，不是模式名称的先进程度。
3. **来源方法**：冲刺 0 只产出愿景与待办，**无增量**；MVA 在后续冲刺产生。
4. **来源方法**：跨团队交接需要**时间差**——同一冲刺内消费上游 MVA 不成立。
5. **项目规则**：2 周时间盒是本项目约定（`R06`），不写进方法本身。
6. **项目规则**：模式切换**不修改旧冲刺历史**（`R08`），旧交接计划关闭但记录保留。
7. **项目规则**：切换是**候选**，需架构委员会复核；能力或授权不足则**保留原模式**（`R07`、`R08`）。

## 转换与推理

1. **先剔除不满足硬条件的备选**。`R05` 给三条排除理由：仅 EA 要"完整产品架构后实施"（项目偏好尽早反馈，故当前不优选；R01 本身未给不可等待的时限，不能称该备选已被事实性硬排除）；三独立团队"缺业务开发容量"（`R01` 说服务台无独立业务开发冲刺容量）；混合跨职能"缺每队业务/EA 能力"（`R02` 说 EA 与开发职责分立）。后两项有明确能力/容量缺口；仅 EA 的取舍还含反馈节奏偏好，不能把三条都称为事实性硬排除。

2. **剩下的选解决方案协作**。`R03` 的设计：EA 冲刺 1 澄清接口并在 DORP1 演示 MVA1；方案冲刺 1 做可抛弃体验样机；**方案冲刺 2 才消费 MVA1**。这个时间差正是 `R05` 排除"同冲刺消费"的依据——交接需要一轮缓冲。

3. **冲刺 0 必须没有增量**。`R04` 说冲刺 0 只确认愿景、范围与待办。若在冲刺 0 的 DORP 里写入一个 MVA 产出，就是"invented-sprint-zero-increment"。这条反例的意义：**冲刺 0 的价值是让后续冲刺有靶子，不是提前交东西**。

4. **DORP 四活动是模式的组成部分，不是可选项**。`R04` 明确 DORP 含演示、成果整理、回顾、下轮规划，未完成项回流。因此任何"跳过 DORP 直接进下一冲刺"的做法都缺了模式的必要构件。

5. **2 周与轮次编号的边界**。`R06` 说 2 周是项目约定，0/1/2/… 是可扩展片段。因此**不能**把"每冲刺对应一个 ADM 阶段"写成规则，也**不能**固定为三轮。轮次是可扩展序列，`R08` 新增"第 4 轮无障碍确认"正是扩展的实例。

6. **切换的三重前置条件**。`R07`+`R08` 给出：①能力事实（两队均具备业务开发、EA、方案三能力）；②授权（在隐私/容量边界内，架构委员会复核）；③继承与关闭（继承 `B-BOOK`/`B-CANCEL`/`G-PRIV`，关闭旧跨团队 MVA 交接计划）。**三者不齐则不切换**——`R08` 明写"若能力或授权不足则保留解决方案协作"。

7. **旧历史不改**。切换后旧冲刺的 DORP 记录、MVA 产出、交接计划**全部保留原样**。旧交接计划"关闭"是新增一条状态变更，不是删除记录。

## 修改演练

改动一处输入：`R07` 的培训材料只证明 DEV-A 具备三能力，DEV-B 仅具备方案能力（缺 EA 与业务开发）。

- 混合跨职能的**前置条件不成立**：每队需具备业务/EA/方案三能力，DEV-B 缺两项。
- `AGS-6` 的结论从"候选切换"改为**"保留解决方案协作"**——这正是 `R08` 已写明的回退分支。
- `R08` 新增"第 4 轮无障碍确认"仍可执行（它不依赖模式切换）。
- 影响：模式选择结论不变（仍为解决方案协作），但**切换候选被否决**。旧冲刺历史依旧不变。

**关键点**：这不是"切换失败"，而是**前置条件检查发挥作用的正常结果**。若因为"已经宣布要切换"就硬切，等于让公告覆盖事实。

反向演练：若 `R05` 的"三独立团队缺业务开发容量"被新证据推翻（三队各补了业务开发人员），则三独立团队重新成为可选。此时**不能自动选它**——仍需比较它与解决方案协作在交接、隐私、支持会安排上的差异。硬条件满足是**必要条件**，不是充分条件。

## 四种模式与选择依据

- 四种模式是互斥备选，不是成熟度等级
- 选择依据是容量、能力、交接需要等事实
- 冲刺 0 无增量，只产出愿景与待办
- 跨团队交接需一轮时间差，同冲刺消费不成立
- 切换需能力与授权双条件，缺一保留原模式

## 反例与输入不足

- **错误做法**：在冲刺 0 的 DORP 里写入一项 MVA 产出。冲刺 0 无增量。预期 `invented-sprint-zero-increment`。
- **错误做法**：方案冲刺 1 与 EA 冲刺 1 在同一冲刺内交接 MVA1。跨团队交接需要时间差。预期 `agile-handoff-timing`。
- **错误做法**：把 EA 到方案的协作画成单向箭头（只有 EA 输出、无反馈）。协作是双向的。预期 `agile-collaboration-semantics`。
- **错误做法**：声明混合跨职能但 DEV-B 缺 EA 与业务开发能力。预期 `cross-functional-capability-gap`。
- **错误做法**：某冲刺结束无 DORP 记录，直接进下一轮。预期 `dorp-boundary-missing`。
- **错误做法**：给四种模式各打 1–4 分，选最高分。模式不是等级。预期 `agile-pattern-as-score`。
- **错误做法**：同时选中解决方案协作与混合跨职能两个模式并同时运行。预期 `agile-selection-not-single`。
- **错误做法**：切换后把旧冲刺的 DORP 记录删除或改写为符合新模式的样子。预期 `missing-evidence`。

**输入不足**：`R05` 只定性说"缺容量/缺能力"，未给具体人数或产能数字，因此排除理由是**定性判断**，不能表述为"产能不足 30%"。`R07` 未给架构委员会复核的时间与议程，`AGS-GAP-1` 保持未决。`R08` 未给第 4 轮无障碍确认的验收标准，该轮的目标需在下一周期规划时补充。
