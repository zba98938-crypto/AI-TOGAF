# 架构描述充分性与正式度：语法正确不等于内容够用

虚构跨馆借阅试点有三份架构描述：一张语法检查通过但漏了冲突分支的"统一读者"图、一份只用于访谈的临时页面草图、一份准备进契约审阅但缺取消语义的接口说明。本案例演练两个**独立**的判断——"内容是否足够支持当前决策"与"当前正式控制是否适合目的"——以及为什么不能把它们压成一个分数。

所有业务材料、人物、评审结论与规则均为虚构教学材料（`BR-01`–`BR-20`）。指南只提供方法依据，项目规则不冒充 TOGAF 规定。

方法：`architecture-description-formality-review-method`。来源方法：G217 §2.4（图 2-1 为方法示意）。
入口：[architecture-description-formality-review-method](../analysis-methods/architecture-description-formality-review-method.md)。
素材：原料（历史材料已清理）、视图（历史材料已清理）。

## 决策与原始业务资料

要回答：**三份描述各自支撑什么决策？支撑得住吗？现在这套正式控制是恰到好处、不足，还是多余？**

| 证据 ID | 原始材料 |
|---|---|
| `BR-12` | 评审材料 `DESC-01` 是一张版本化、通过语法检查的"统一读者"图；它**遗漏乙馆与丙馆的身份冲突和人工复核责任**。当前决策是能否开始接口契约评审，故它**内容不足**，即使已经使用正式模型表示。 |
| `BR-13` | `DESC-02` 是给内部访谈的临时预约页面草图，只用于判断读者是否理解跨馆取书。已有访谈目的、对象和问题，**尚无需求可行性证据**；此时要求完整生产部署与容灾模型**会增加与当前决策无关的工作**。项目只要求标明假设、边界与版本。 |
| `BR-14` | `DESC-03` 是准备进入契约审阅的预约接口说明，已有输入输出、错误码、消费者、范围、版本和待决问题；它**仍缺 `BR-07` 的取消状态**。因此在该问题补齐前只能作为**审阅草稿**，不能宣称足够支持发布，**也不能把 approved 当成正式度**。 |
| `BR-20` | 描述评审使用"**是否足够支持指定决策**"和"**当前正式控制是否适合目的**"两独立判断，采用**文字理由**，**不使用数值等级或总分**。 |

## 来源规则与项目规则

1. **来源方法（G217 §2.4）**：架构描述的充分性相对于**特定决策**而言——同一份描述对决策 A 足够、对决策 B 不足，是正常结论而非矛盾。
2. **来源方法**：正式度（formality）由一组**控制手段**构成（版本标识、建模记法、语法检查、评审记录等），不是单一等级。
3. **来源方法**：充分性与正式度是两个维度，不能互相替代或互相折算。
4. **项目规则（`BR-20`）**：判断以文字理由表达，**禁止数值等级、禁止加权总分**。
5. **项目规则**：`evolution_state`（target / baseline / transition）与 `approval_state`（approved / candidate / rejected）**分列记录**，不得合并为"状态"一个字段。
6. **项目规则**：`approved` 只是审批态的一种取值，**不是正式度评级**（`BR-14` 明示）。

## 转换与推理

1. **先固定"决策"，再谈"够不够"**。三份描述对应三个不同决策：
   - `REV-01`：是否可以开始预约契约评审（`BR-12`）。
   - `REV-02`：是否可开始内部访谈以验证取书概念（`BR-13`）。
   - `REV-03`：是否可以完成预约契约的内容审阅（`BR-14`）。
   
   决策不同，充分性标准就不同——这是本方法的核心，也是"同一张图有人说过剩有人说不足"的解法。

2. **`REV-01`：控制齐备但内容不足**。`current_formality` 有版本标识、正式建模记法、语法检查三项；`formality_fit` 写 `control-present-content-insufficient`。推理：语法检查只证明**记法合法**，不证明**覆盖完整**。遗漏乙/丙馆冲突与人工复核责任，直接导致"能否开始契约评审"这个决策缺少必要信息 ⇒ `sufficiency=insufficient`。

3. **`REV-02`：访谈内容可用，最低控制仍需补，多加生产模型则过度**。`current_formality=["临时草图"]`；`needed_formality=["假设标注","范围边界","版本标记"]`；`formality_fit=additional-production-model-would-be-excess`。推理：当前决策是"能不能去访谈"，不是"能不能上线"。此时要求生产部署与容灾模型，与决策**无关**，属于把正式度当目的而非手段。

4. **`REV-03`：控制合适但内容有缺口**。`formality_fit=appropriate-controls-with-content-gap`。已有输入输出、错误码、消费者、范围、版本、待决项——这些控制**恰好匹配**契约审阅所需；但取消重约语义缺失使内容审阅无法完成 ⇒ 只能作审阅草稿。这里两个判断给出**不同**结论：正式控制 fit，内容 insufficient。若压成一个分数，这个关键差异就被平均掉了。

5. **状态分列**。三项均为 `evolution_state=target`、`approval_state=candidate`。`candidate` 表示尚未获批，与"正式度高低"无关。特别地，`REV-03` 若把 `approval_state` 误读为"正式度=approved 高"，会得出"既然 approved 就够正式"的错误结论。

6. **每项给出可执行动作**。`REV-01` 动作"补乙/丙馆和冲突分支、指定人工复核责任"；`REV-02` 动作"标注假设、边界与版本，访谈后再决定产品架构深度"；`REV-03` 动作"补取消重约约束及验证证据，复核是否可完成内容审阅，发布批准另行"。动作必须收窄到**能让判断翻盘**的那一件事。

7. **修改后的复评**。`BR-18` 声明 `DESC-03` 加入取消证据后足以支持契约审阅 ⇒ `REV-03.sufficiency` 从 `insufficient` 改为 `sufficient-for-stated-decision`，`formality_fit` 仍为 `appropriate-controls`（控制手段没变，只是内容补齐了）。这一条最清楚地说明两判断独立：**只有内容维度变了，正式度维度不变**。

本方法采用定性判断与追溯演练，没有适用的统一计算器。**充分性与正式度都不折算为分数**：本案例不给 1–5 级、不给百分比、不给两维加权。理由不是"暂时没做"，而是 `BR-20` 明确规定用文字理由——任何分值化的"正式度指数"都会掩盖 `REV-03` 那种"控制 fit 但内容 gap"的组合。

## 两个独立判断的对照

| 判断 | 回答什么 | 本案 `REV-03` 结论 |
| --- | --- | --- |
| 充分性 | 内容够不够支持**这个**决策 | `insufficient`（缺取消语义） |
| 正式度 | 当前控制是否适合目的 | `appropriate-controls`（控制齐备） |

**两者可以不一致**，本案正是如此。若压成一个分数，"控制合适但内容有缺口"这个关键信息会被平均掉。

## 充分性随决策变化

| 决策 | 同一份描述的充分性 |
| --- | --- |
| 能否开始契约评审 | 需冲突分支与责任 |
| 能否开始内部访谈 | 需假设、边界、版本 |
| 能否完成内容审阅 | 需状态约束完整 |

**同一张图对不同决策的充分性不同**，这不是矛盾，是方法的定义。

## 正式度是控制集合，不是等级

| 控制 | 作用 |
| --- | --- |
| 版本标识 | 可区分前后版本 |
| 建模记法 | 可被工具解析 |
| 语法检查 | 结构合法 |
| 评审记录 | 有人看过 |

控制齐备不等于内容完整——**语法正确只证明记法合法**。

## 修改演练

改动一处输入：`BR-18` 声明 `DESC-03` 已加入取消与重新预约的状态约束，并有 `DEMO-02` 验证。

- `REV-03.sufficiency`：`insufficient` → `sufficient-for-stated-decision`；`sufficiency_evidence` 改写为"取消重约约束已补并有 DEMO-02 验证"。
- `REV-03.formality_fit`：`appropriate-controls-with-content-gap` → `appropriate-controls`（**控制手段没变**，是内容补齐使匹配成立）。
- `REV-03.actions`：从"补取消重约约束"改为"进入内容审阅；发布批准另行申请"。
- `REV-03.approval_state`：**仍为 `candidate`**。内容够了不等于批准了；这两件事在本方法里彻底分开。
- 影响视图：仅 `v-architecture-description-formality-table` 的 `REV-03` 行。`REV-01`、`REV-02` 不变。

反向演练：若有人主张"既然 `REV-02` 的草图足够，那 `REV-01` 的正式图也应该足够"——这是把**正式度**当**充分性**。`REV-01` 的正式度高（有版本、记法、语法检查）但内容不足；`REV-02` 内容可支持访谈目的，但最低正式控制尚待补齐。二者不构成推理关系。

第三种演练：若把 `REV-02` 的决策改为"是否可批准生产上线"，则 `sufficiency` 必须翻为 `insufficient`，`needed_formality` 必须扩为含部署与容灾。**同一份描述，换决策就换结论**——这正是方法要保住的判断力。

## 反例与输入不足

- **错误做法**：因 `DESC-01` 通过语法检查就判 `sufficiency=sufficient`。记法合法不等于覆盖完整。预期 `missing-evidence`。
- **错误做法**：把 `approval_state=approved` 填进 `current_formality` 并据此判正式度高。审批态不是正式度。预期 `formality-state-conflation`。
- **错误做法**：要求 `DESC-02` 附完整生产部署与容灾模型才允许访谈。与当前决策无关的控制是浪费。预期 `missing-evidence`。
- **错误做法**：给三项评审各打 1–5 分并算平均 3.7 作为"整体充分性"。`BR-20` 禁止数值等级与总分。预期 `unsourced-maturity-rating`。
- **错误做法**：把 `evolution_state` 与 `approval_state` 合并为一个 `status` 字段，值为 `target-approved`。两态语义不同，合并即丢信息。预期 `formality-state-conflation`。
- **错误做法**：`REV-03` 的 `decision` 写"是否可以发布"，但 `actions` 只写"补文档格式"。决策与动作不对应。预期 `missing-evidence`。

**输入不足**：`BR-12` 未说明乙馆与丙馆冲突的具体形态（是标识冲突、优先级冲突还是责任冲突），只写"身份冲突"。因此 `REV-01.actions` 只能写"补乙/丙馆和冲突分支"，不能代为指定冲突类型。`BR-13` 未给访谈样本量与判定标准，`REV-02` 不能预设"访谈 10 人即算验证通过"。

## 评审记录

- 核对三项评审各自绑定唯一且明确的决策陈述。
- 核对 `REV-01` 的"控制齐备/内容不足"结论有遗漏项原文支撑。
- 核对 `REV-02` 的"多加即过度"结论指向具体无关控制（生产部署、容灾）。
- 核对 `REV-03` 的两维结论不一致（fit + gap），且该不一致被明确表述而非平均掉。
- 核对全表无等级、无权重、无总分，理由字段均为文字。
- 核对 `evolution_state` 与 `approval_state` 分列，无合并字段。
- 核对修改演练中只有内容维翻转、正式度维保持。
- 核对"换决策即换结论"被显式演示。
