# 微服务数据分布：快照过期就转人工

## 决策与原始业务资料

资格服务如何在不直接读读者主库的前提下，保持数据新鲜且可判定？

| 证据 ID | 原始材料 |
|---|---|
| `msa-d1` | 每晚经受控导出取得读者资格快照，以保持运行独立性。 |
| `msa-d2` | 两分片按 `readerId` 哈希；保留 2 个版本。 |
| `msa-d3` | 快照超过 24 小时，**拒绝给出肯定资格**并转人工。 |
| `msa-d4` | 缓存不超过快照有效期；属性密级取 `internal < confidential` 中的高者。 |
| `msa-d5` | 没有跨服务直接访问数据库。 |

## 来源规则与项目规则

1. 来源方法（G21I）：服务应拥有自己的数据副本，通过契约获取，不共享数据库。
2. 来源方法：数据分布需说明分片、副本、新鲜度与失败处置。
3. 项目规则：**过期不是降级为"默认通过"，而是拒绝肯定**（`msa-d3`）——安全侧失败。
4. 项目规则：缓存不得越过快照有效期（`msa-d4`），否则缓存成为绕过新鲜度检查的通道。
5. 项目规则：属性密级取高者（`msa-d4`），不做宽松合并。

## 转换与推理

1. **数据流向是单向的，这是全部安全性的基础**：

   ```
   主库 →（受控导出）→ 快照 → 分片存储 → 服务读取
   ```

   **本候选数据流未定义反向写入；无跨库访问不单独证明经接口也绝无写回**。`msa-d5` 明说没有跨服务直接访问数据库。若服务能反写主库，快照与主库的权威关系就倒了，过期判定也失去意义。

2. **新鲜度以数据 as-of 时刻为基准**。判定基准是**快照数据的 as-of 时刻（导出时刻只有在证实与源数据水位一致时才可代用）**，不是服务查询的时刻，也不是缓存写入的时刻。`msa-d3`：快照超过 24 小时，**拒绝给出肯定资格**并转人工。

3. **过期处置是"安全侧失败"，不是降级**。这是本案例最关键的判断：

   | 处置方式 | 后果 |
   | --- | --- |
   | 返回旧值 + 标注过期 | 调用方可能忽略标注 ⇒ **不安全** |
   | 返回"无法判定" + 转人工 | 业务变慢，但不会误放行 ⇒ **安全** |
   | 默认通过 | 直接失效 ⇒ **最差** |

   `msa-d3` 选的是第二种。**用可用性换正确性，这是有意识的取舍，不是缺陷。**

4. **分片与历史版本**（历史版本不等于高可用副本）。按 `readerId` 哈希分两片，每片保留 2 个版本。哈希分片的意义是**同一读者的数据始终落在同一片**，避免跨片查询；保留 2 个版本支持回滚到上一版。

5. **缓存不得越过快照有效期**。`msa-d4`：缓存 TTL ≤ 快照剩余有效期。若快照剩余 2 小时，缓存不得超过 2 小时。**否则缓存会变成绕过新鲜度检查的通道**——服务看着是"新鲜"的，实际读的是过期快照里的值再缓存了一份。

6. **密级取高者，不做宽松合并**。同一读者的不同属性密级不同时，服务整体按最高密级处理。理由：若按低密级输出，调用方可能通过低密级字段的返回与否**推断**高密级内容。

## 失败处置的三个档位

- 拒绝肯定：无法判定时不给肯定结论，转人工（本案采用）
- 返回旧值并标注：可用优先，但依赖调用方尊重标注
- 默认通过：最差，等于检查失效
- 档位选择是安全与可用的取舍，须显式声明而非默认继承
- 分片键选择：须保证同一实体落在同一片（如按 readerId 哈希），避免跨片查询
- 副本保留版本数决定回滚窗口，同时须定义何时淘汰最旧版本

## 修改演练

**情景一：过期策略改为"返回上次结果并标注过期"**。风险在于**调用方可能忽略标注直接使用**——安全侧失败变成可用侧优先。此变更须**调用方逐一确认能处理标注**，否则不可改。这不是技术改动，是跨方契约改动。

**情景二：保留版本从 2 增到 3**。仅在各版本等大、全量保存且其他存储不变时，版本数据量上升50%；版本间隔不变时回滚跨度可能增大，不能把它当作总存储或成本必增50%。但需同时说明**何时淘汰最旧版本**，否则版本会无限累积。回滚能力与存储成本需一起决定。

**情景三：快照导出失败**。`MSA-DGAP-1` 未定义处置。可接受的选项是"继续用上一份快照直至超过 24 小时，然后拒绝肯定"；不可接受的是"导出失败就跳过新鲜度检查"。**缺口不填，不等于可以绕过规则。**

**情景四：某属性的密级从 `confidential` 降为 `internal`**。需重算该读者整体密级（取高者）。若该读者还有其他 `confidential` 属性，整体仍为 `confidential`——**单项降级不自动导致整体降级**。

**影响范围**：情景一改动跨方契约与失败语义；情景二改动存储与淘汰规则；情景三需补齐缺口定义；情景四只影响密级计算，不影响数据流向。

## 反例与输入不足

- **错误做法**：快照过期时返回上次的肯定资格。违反 `msa-d3`。预期 `missing-evidence`。
- **错误做法**：缓存 TTL 设为固定 1 小时，而快照剩余有效期只有 10 分钟。缓存成为绕过通道。预期 `missing-evidence`。
- **错误做法**：服务直接连读者主库读最新值。违反数据边界。预期 `relation-endpoint-type`。
- **错误做法**：以服务查询时刻为新鲜度基准，而非快照数据 as-of 时刻。查询时刻永远新鲜，检查形同虚设。预期 `measurement-basis-gap`。
- **错误做法**：因某字段密级为 `internal` 就按 `internal` 输出，忽略同记录其他 `confidential` 字段。可用低密级字段推断高密级内容。预期 `missing-evidence`。
- **错误做法**：导出失败时跳过新鲜度检查以"保持可用"。缺口未定义不等于可绕过。预期 `approval-without-evidence`。
- **错误做法**：把读者数据按姓名哈希分片。同名读者会落到同片，且姓名可变更。预期 `partition-key-stability-gap`（同名落同片是正常哈希碰撞，不是 ID 重复；问题是姓名可变导致同实体迁片）。

**输入不足**：`msa-d1` 的导出失败处置未定义（`MSA-DGAP-1`）。`msa-d3` 未给转人工后的判定时限与责任方（`MSA-DGAP-2`）。材料未证明数据 as-of 水位等于导出时刻，导出新不保证数据新；也未给快照数据量，故不估算导出耗时与存储需求。

## 评审记录

- 核对数据流单向，无反向写入与跨库直连。
- 核对过期策略为安全侧失败（拒绝肯定 + 转人工），未降级为返回旧值。
- 核对新鲜度需数据 as-of 水位，导出时刻不能掩盖源数据已陈旧的时间或缓存写入时刻。
- 核对缓存 TTL 与快照有效期绑定，未设固定值。
- 核对密级取高者，且说明了可推断风险。
- 核对分片键为 `readerId` 哈希，保证同读者同片。
- 核对历史快照保留 2 版；未给独立副本数并支持回滚，但未定义淘汰规则。
- 核对两项缺口（导出失败处置、转人工时限）保留。
- 核对四项修改情景分别说明影响范围与不可绕过的规则。
- 核对分片键保证同实体同片，未使用可变且可重复的属性。
- 核对副本保留版本数与淘汰规则成对出现，未只定义其一。
- 核对"转人工"的判定时限与责任方虽未定义，但已在反例章节列为缺口而非默认处理。
