## 来源规则与项目规则

1. **来源方法（G203）**：六级九要素是 G203 给出的模型示例，不是所有组织强制采用的唯一成熟度模型；等级是序数而非等距数值。
2. **来源方法**：成熟度评估以逐级证据为基础，缺少证据的等级不成立。
3. **项目规则**：等权汇总、取"最高完整满足级别"、未知要素如何处理，均为本案例显式采用的项目规则；不发明通过线。
4. **项目规则**：不把等级差（如 3−2）解释为等距能力缺口，也不用平均分或自定分数线替代逐级证据。

**来源依据**：`references/capability-addenda/acmm-maturity-assessment.md`；本案所有阈值与汇总方式均标注为项目规则。

## 转换与推理

1. 将九份原始观察分别对照要素特征，逐项保留1/2/3级的证据清单；不足的高一级特征保留为不满足或未知。
2. 形成分值[3,3,2,2,2,3,2,2,1]，九项权重均为1；逐级达成输入显式给出，不由计算器推断。
3. 只汇总已采用的规则：加权等级20/9；1级九项、2级八项、3级三项、4/5级零项。0级“没有EA计划”不纳入累计达成百分比分母列表。
4. 改进优先顺序结合项目目标：采购参与不足影响本轮选型，因此先补采购合规工作；不是仅因最低分就自动确定预算。

5. **"取最高完整满足级别"不是"取平均"或"取最高单项"**。规则是：对每个要素，找到**所有特征都满足**的最高级别。因此：
   - 若某要素满足 1、2 级全部特征，但 3 级只满足部分 ⇒ 该要素评级为 **2**
   - 不能因为"3 级满足了 3 项中的 2 项"就记 3
   
   这个规则使等级成为**阶梯式**判断，不是分数累加。

6. **未知不等于 0**。`acmm-rule` 明确"未知不计 0"。这两者的区别：

| 处置 | 含义 | 对汇总的影响 |
| --- | --- | --- |
| 记为 0 | 断言"该特征不满足" | 拉低平均值 |
| 记为未知 | 承认"没查/没证据" | **保留缺口，不参与断言** |

   把未知记 0，会让"没做调查"看起来像"能力不足"。本案九项均有观察，故无未知项。

7. **0 级要单列，不能混入统计**。`acmm-rule` 说 0 级"无 EA 计划"单列状态，**不当作所有成熟组织自动达成的低级特征**。理由：
   - 0 级的含义是"根本没有 EA 活动"
   - 若把 0 级当作"人均已达成的起点"，任何有 EA 活动的组织都会显得"高于基线"
   
   本案九个要素均 ≥1 级，故 0 级不参与累计百分比的分母计算。

8. **逐级达成清单必须逐条核对，不能从分值倒推**。材料反复强调"本例评审包同时逐条确认所列已达成级别的适用特征；不是从最终分值倒推"。这一点至关重要：
   - 正确方向：证据 → 特征满足 → 要素级别 → 汇总
   - 错误方向：汇总值 → 反推级别 → 声称特征满足

   倒推会让"平均 2.22"这种数字看起来像有九个独立的等级判断支撑，实际上可能只有一个数字。

9. **汇总值 2.222222 不是"2 级认证"**。ACMM-SCORE 明确"这不是已获组织等级2认证"。区分：
   - 汇总值：九个要素等级的算术平均（项目规则规定等权）
   - 认证等级：由授权机构按正式程序评定的等级

   **本案只有前者，没有后者。**

## 修改演练

**情景一：v2 采购证据支持 3 级**。`acmm-investment-new` 说采购战略、合规检查与成本效益分析已在三次采购使用，且逐项复核 1/2/3 级特征满足，4 级仍未达。此时：
- 该要素评级从 1 升到 **3**
- 汇总从 20/9 = 2.222222 变为 22/9 = **2.444444**
- 3 级达成数从 3 项变为 **4 项**（4/9 = 44.444%）
- **其余八行不变**

**情景二：某要素发现证据不足，需降级**。评级下降，汇总相应下调。**但历史评级记录必须保留**——不能覆盖，否则无法解释"为什么上次是 2 这次变 1"。

**情景三：某要素完全无证据**。按规则记"未知"而非 0。汇总时分母是否包含该要素，取决于项目规则；若规则未定义，则不能自行决定——**这是规则缺口，不是数据缺口**。

**情景四：业务方要求"四舍五入到 2.5 级"**。等级是序数，**序数不能四舍五入**——2.5 级不对应任何特征集合。汇总值可以有小数的算术意义，但不能被当作"介于 2 级与 3 级之间的等级"。

**影响范围**：情景一改变单行与两处汇总值；情景二降级并保留历史；情景三暴露规则缺口；情景四涉及序数误用。四种情形下"逐条核对而非倒推"的要求不变。

## 反例与输入不足

- **错误做法**：去掉 `rule_evidence` 字段后仍要求生成等级。实际计算失败。预期 `unsourced-maturity-rating`（等级没有逐级证据）。
- **错误做法**：只有分值、没有逐级评据时仍生成 `achieved_levels`。分值不是证据。预期 `unsourced-maturity-rating`。
- **错误做法**：出现未知要素时自动填 0 或从分母删去。未知不得当零，也不得删除。预期 `measurement-basis-gap`。

**输入不足**：材料未给各要素的评据来源清单，因此本轮的等级只能标为候选；裁剪规则若未声明，任何等级都不成立。
