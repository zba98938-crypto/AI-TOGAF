# EA 服务与 ADM 映射：项目安排不是来源表格

所有业务资料、人物、数值、政策及证据均为虚构教学材料；指南只提供方法依据，项目规则不冒充 TOGAF 规定。案例完整演练不等于独立业务评审通过。

入口：[ea-service-adm-evidence-map-method](../analysis-methods/ea-service-adm-evidence-map-method.md)。

## 决策与原始业务资料

哪些 EA 服务在哪些 ADM 阶段被实际使用？

| 证据 ID | 原始材料 |
|---|---|
| `ea-a1` | 项目会议把价值评估用于愿景 A。 |
| `ea-a2` | 消费者变化建议用于 H。 |
| `ea-a3` | 合规准则准备作为 G 实施评审的输入。 |
| `ea-a4` | 服务名称与候选目录来自 G217；**源图 C-1 逐格映射本轮未核实**，因此这些映射只作项目操作记录。 |

## 来源规则与项目规则

1. 来源方法（G217）：EA 服务是交付架构能力的机制，可在特定 ADM 阶段被消费。
2. 来源方法：服务与阶段的对应需有证据，不能凭"看起来相关"。
3. 项目规则：**未核实的映射只记项目操作，不作来源结论**（`ea-a4`）。
4. 项目规则：一个服务可用于多个阶段，但每次使用需单独记录输入输出。

## 转换与推理

1. **三段映射**：

| 服务 | ADM 阶段 | 用途 | 证据 |
| --- | --- | --- | --- |
| 价值评估 | A | 形成愿景 | `ea-a1` |
| 消费者变化建议 | H | 变更触发评估 | `ea-a2` |
| 合规准则准备 | G | 实施评审输入 | `ea-a3` |

2. **输入输出明确化**：
   - 价值评估 → A：输出是愿景的范围与价值主张，不是完整业务架构。
   - 消费者变化建议 → H：输出是变更候选，不是已批准的变更请求。
   - 合规准则准备 → G：输出是评审输入清单，不是合规结论。
3. **未核实标注**：`ea-a4` 明确逐格未核。因此本表是项目记录，不得引用为"G217 图 C-1 第 X 行"。
4. **缺失阶段**：B–F 无 EA 服务使用记录。这是"未记录"，不是"不需要"。

5. **映射的证据是"被使用"，不是"相关"**。`ea-a1`–`ea-a3` 给的是会议与准备记录：
   - 价值评估**被用于**愿景 A（会议记录）
   - 变化建议**被用于** H（消费者记录）
   - 合规准则**准备作为** G 的输入（准备记录）

   前两项是材料记录的使用，G 项只是准备输入、是否实际被采纳未知；不能把三者都称作已使用事实。它们不是"这两个概念看起来相关"。后者会产生大量无证据的映射。

6. **每个映射要写明"输出是什么、不是什么"**。这是本方法最容易被简化的地方：

| 服务 → 阶段 | 输出是 | 输出不是 |
| --- | --- | --- |
| 价值评估 → A | 愿景的范围与价值主张 | 完整业务架构 |
| 变化建议 → H | 变更候选 | 已批准的变更请求 |
| 合规准则 → G | 评审输入清单 | 合规结论 |

   **"不是什么"比"是什么"更重要**——它防止下游把半成品当成品用。

7. **B–F 空白是"未记录"，不是"不需要"**。与 N/P/D 案例的空白处理一致：缺记录只说明没有证据，不说明该阶段不需要 EA 服务。若读成"不需要"，会永久关闭这些阶段的 EA 介入可能。

8. **未核实标注的作用域**。`ea-a4` 说源图 C-1 逐格映射本轮未核实。因此：
   - 本表可作**项目操作记录**
   - 不可引用为"G217 图 C-1 第 X 行第 Y 列"
   - 不可用于论证"标准要求在此阶段使用该服务"

   服务名称与候选目录来自 G217，这部分是来源事实；**逐格对应关系是本项目判断**。

9. **一次使用一条记录**。项目规则说一个服务可用于多个阶段，但**每次使用需单独记录输入输出**。若把"价值评估用于 A、B、C"合并成一条"价值评估用于 A–C"，三次使用的输入输出差异就消失了。

## 修改演练

**情景一：B 阶段也使用价值评估**。需新增一条**独立的**使用记录（含输入输出），不能把它并进 A 的那条。同一服务两次使用的上下文不同。

**情景二：源图 C-1 被核实，且某格与原记录一致**。该格可从"项目记录"升级为"来源转录"，但**只限被核实的那一格**，其余仍为项目记录。

**情景三：合规准则在 G 被用作"合规结论"**。这与 `ea-a3` 的"准备作为输入"不同。若实际用法是出结论，则该映射的输出描述需修正，且责任归属随之改变——出结论的是评审方，不是服务提供方。

**情景四：业务方要求"补齐 B–F 的映射"**。可行做法是逐阶段调查是否有使用；**不可行做法**是按 A/H/G 的模式推测 B–F 也该有。**推测出来的映射不是证据。**

**影响范围**：情景一新增记录；情景二改变单格出处；情景三修正输出描述与责任；情景四扩展调查范围但不改变证据标准。四种情形下"未核实标 not-verified"的要求不变。

## 反例与输入不足

- **错误做法**：把项目记录写成"G217 图 C-1 规定合规准则用于 G 阶段"。逐格未核。预期 `missing-evidence`。
- **错误做法**：因 B–F 无记录就判定这些阶段不需要 EA 服务。未记录不等于不需要。预期 `missing-evidence`。
- **错误做法**：把"消费者变化建议"的输出当成已批准变更请求。它只是变更候选。预期 `approval-without-evidence`。
- **错误做法**：把 B–F 的空白填成"该阶段不需要 EA 服务"。未记录不等于不需要。预期 `missing-evidence`。
- **错误做法**：引用"G217 图 C-1 第 2 行"作为映射依据。逐格未核实。预期 `missing-evidence`。
- **错误做法**：把"合规准则准备作为 G 的输入"写成"合规准则在 G 给出合规结论"。输出描述越界。预期 `core-vocabulary-override`。
- **错误做法**：把价值评估在 A、B、C 的三次使用合并为一条记录。每次使用需单独记录输入输出。预期 `missing-evidence`（多次使用上下文被合并，不必然是 ID 重复）。
- **错误做法**：按 A/H/G 的模式推测 B–F 也应有映射。推测不是证据。预期 `missing-evidence`。
- **错误做法**：把"服务名称来自 G217"当作"逐格映射也来自 G217"。前者是来源事实，后者是项目判断。预期 `core-vocabulary-override`。

**输入不足**：`ea-a4` 明示源图 C-1 逐格未核实，因此全部映射保持项目记录状态（`EAA-GAP-1`）。材料未给 B–F 阶段的 EA 活动记录，无法判断是否真的未使用。`ea-a3` 只说"准备作为输入"，未给实际是否被采纳。

## 评审记录

- 核对每段映射的输入输出明确，未停留在"某服务用于某阶段"。
- 核对全部标注为项目操作。
- 核对未记录与不需要被区分。
- 核对服务输出与批准状态分离。
- 核对缺口保留。
- 核对每项映射的"输出是什么/不是什么"分别写明，未只写前者。
- 核对 B–F 空白未被填成"不需要"。
- 核对四项修改情景分别说明影响范围与不变项。
