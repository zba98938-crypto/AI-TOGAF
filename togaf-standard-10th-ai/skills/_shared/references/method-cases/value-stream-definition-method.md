# 定义顾客取得可用商品的价值流

所有业务资料、人物、数值、政策及证据均为虚构教学材料；指南只提供方法依据，项目规则不冒充TOGAF规定。案例完整演练不等于独立业务评审通过。

方法：`value-stream-definition-method`。来源方法：G178 §3–4。
入口：[value-stream-definition-method](../analysis-methods/value-stream-definition-method.md)。

## 决策与原始业务资料

找到顾客价值在哪个阶段受阻，并关联使能能力。

|证据 ID|原始材料|
|---|---|
|vs-1|顾客访谈：我需要在承诺日期收到可使用的商品，而不只是收到订单确认。触发是确认购买意愿。|
|vs-2|运营记录：订单确认后由库存团队准备商品、承运方配送；交付后仍有损坏品争议。|
|vs-3|业务约定：可用性由顾客验收或约定到期无争议确认；争议处理留在本价值流范围。没有统一完成时限。|

## 来源规则与项目规则

1. 来源方法：价值流从受益者及最终价值出发，阶段是价值递进，能力可跨阶段复用。
2. 项目约定：每阶段记录进入/退出、受益者获得价值及负责方；阶段先后不是详细流程控制流。

## 转换与推理

1. **受益者与最终价值先定，阶段才有边界**。受益者 `ST-1` 是顾客，最终价值 `V-1` 是"取得可用商品"。订单录入、库存查询是**实现活动**，不因系统里有这个功能就成为价值阶段——价值阶段的判据是"受益者在此阶段获得的价值发生了递进"，不是"系统在此处有功能"。

2. **四个阶段的进入/退出条件**：
   - `S-1` 形成可信承诺：进入＝购买意愿，退出＝可履行承诺
   - `S-2` 备妥商品：进入＝已承诺，退出＝可交运
   - `S-3` 取得商品：进入＝可交运，退出＝顾客接收
   - `S-4` 确认可用：进入＝已接收，退出＝验收完成或争议解决

   每一阶段的"退出"就是下一阶段的"进入"，这条链是价值递进的证据；阶段间若出现空档或交叉，说明定义有误。

3. **能力跨阶段复用，不复制对象**：
   | 能力 | 使能阶段 |
   | --- | --- |
   | `C-1` 承诺管理 | `S-1` |
   | `C-2` 库存管理 | `S-1`、`S-2` |
   | `C-3` 交付管理 | `S-3` |
   | `C-4` 客户服务 | `S-1`、`S-4` |

   `C-2` 与 `C-4` 各自使能两个阶段，**复用同一 ID**。若为每个阶段复制一份能力，会得到四条看似独立实则同一的能力，相关能力变更需更新各自两份副本。

4. **争议处理留在范围内**。`vs-2` 提到"交付后仍有损坏品争议"，`vs-3` 明确争议处理留在本价值流。因此 `S-4` 的退出条件是"验收完成**或**争议解决"——两个分支都算阶段结束，不是只有"验收成功"才算。

5. **缺口要指向能力实例，而非指标**。损坏争议追溯到 `S-4` 退出不确定，登记 `GAP-V1` 为"缺少可追溯验收结果"，指向 `C-4` 的能力实例补充。**不能**改成"提升配送速度指标"——配送速度与损坏争议是两件事，后者需要的是验收记录，不是更快的送达。

6. **不估时限**。`vs-3` 明确"没有统一完成时限"，因此每阶段的时长只能标为待约定（`GAP-V2`），不得用"步骤数 × 平均时长"推算交付周期。

## 输出与追溯

| 结果 ID | 结论 | 追溯 | 状态 |
|---|---|---|---|
| `VS-1` | `S-1`→`S-2`→`S-3`→`S-4`，价值由可信承诺递进到可用性确认 | `vs-1`/`vs-2`/`vs-3` | 候选定义 |
| `VS-2` | 四阶段进入/退出条件两两衔接，无空档 | `vs-1`/`vs-3` | 已核对 |
| `VS-3` | `C-2`、`C-4` 跨阶段复用同一 ID，未按阶段复制 | `vs-2` | 已核对 |
| `VS-4` | 争议处理在范围内，`S-4` 退出含"或争议解决"分支 | `vs-2`/`vs-3` | 已声明 |
| `GAP-V1` | 补充验收和争议记录能力实例，不自动认定配送更快能解决损坏 | `S-4` → `C-4`；`vs-2` | 优先调查 |
| `GAP-V2` | 每阶段时限等待业务约定，不以步骤数估算交付时间 | `vs-3` | 待补 |

本方法采用定性判断与追溯演练，没有适用的统一计算器。**方法输出的边界**：给出阶段划分、进入/退出条件与能力映射，**不给出**周期时长、成本或产能——`vs-3` 明示无统一时限，任何时长数字都会是编造。

## 阶段定义的四个必备项

每个阶段必须能回答四个问题，缺一即无法判定阶段边界：

| 项 | 回答 | 本案 S-2 实例 |
| --- | --- | --- |
| 进入条件 | 什么情况下进入此阶段 | 已承诺 |
| 退出条件 | 什么情况下离开此阶段 | 可交运 |
| 受益者获得什么 | 价值如何递进 | 商品已备妥 |
| 负责方 | 谁对此阶段负责 | 库存团队备货（vs-2）；正式问责主体待确认 |

**"进入＝上一阶段退出"是链式校验**。若某阶段的进入条件与上一阶段的退出条件不一致，价值流定义就有断点。本案四阶段两两衔接，无断点。

## 价值流与流程、价值链的区别

三者常被混用，判据不同：

| 概念 | 判据 | 本案对应 |
| --- | --- | --- |
| 价值流 | 受益者的价值如何递进 | `S-1`→`S-2`→`S-3`→`S-4` |
| 流程 | 步骤、分支、角色如何执行 | 未在本案例定义 |
| 价值链 | 企业活动的宏观分段 | 不是顾客价值流 |

**价值流不描述控制流**。阶段先后是价值顺序，不是"必须按此顺序执行"。若需要描述并行、分支与审批，那是流程类工件的职责。

## 能力映射的复用规则

同一能力可跨阶段复用，**不按阶段复制**：

| 能力 | 使能阶段 | 若复制会怎样 |
| --- | --- | --- |
| `C-2` 库存管理 | `S-1`、`S-2` | 两个 ID 需同步维护 |
| `C-4` 客户服务 | `S-1`、`S-4` | 同上 |

复制能力的实际代价：任何能力变更要改多处，且"这是同一个能力"这一事实消失。

## 修改演练

**情景一：新增自提渠道**。`S-3`（取得商品）的实现方式换成门店交接，`S-3` 的 ID 与顾客价值（"取得可用商品"）**保持不变**——渠道变了，价值没变。若因此新建 `S-3b` 阶段，会让同一条价值流出现两个"取得商品"。

**情景二：受益者改为供应商收款**。这不是"换个标题"，而是**新建一条价值流**：受益者变了，最终价值从"顾客取得可用商品"变为"供应商收到货款"，阶段划分与能力映射都需重做。为新价值流建立新的受益者/价值/阶段身份；原 ST-1、V-1、S-1–S-4 留在原顾客价值流与历史中，不能被删除或覆盖。

**情景三：`GAP-V1` 补齐验收记录**。S-4 的退出仍须满足验收/约定到期无争议确认或争议解决；新增可追溯记录只是验证证据，不能用记录存在代替结果达成，`C-4` 的能力实例增加验收记录组成。争议仍可能存在，但**争议的判定有了依据**——这是修复的实质。

**影响范围**：情景一仅改 `S-3` 的实现；情景二使价值流整体重建；情景三补 S-4 退出的验证证据与 C-4 组成，不自动修改业务退出条件。三种情形下 `V-1` 的表述是否变化，是判断"是否同一条价值流"的关键。

## 反例与输入不足

- **错误做法**：把研发、采购、生产、销售这类企业价值链区块直接当作本顾客价值流阶段。价值链分段不等于顾客价值递进。预期 `core-vocabulary-override`。
- **错误做法**：以阶段横向排列证明价值递进关系。排版不是证据。预期 `missing-evidence`。
- **错误做法**：省略触发条件与受益者退出条件，只画中间阶段。缺首尾即无边界。预期 `missing-evidence`。
- **错误做法**：为 `C-2` 在 `S-1` 和 `S-2` 各建一个能力 ID，认为"不同阶段的能力不同"。同一能力跨阶段复用，复制会产生需同步维护的两份定义。预期 `duplicate-id`。
- **错误做法**：把 `S-3` 的退出条件写成"顾客签收"，并据此判定价值已实现。签收是接收，不等于商品可用；`S-4` 的存在正是为此。预期 `core-vocabulary-override`。
- **错误做法**：以"4 个阶段 × 平均 2 天"推算价值流周期。`vs-3` 明示无统一时限。预期 `measurement-basis-gap`。

**输入不足**：材料明确"没有统一完成时限"，因此本案例不给价值流的时长结论。`vs-2` 只提到"损坏品争议"存在，未给争议发生率与处理时长，故 `S-4` 的争议分支无法量化。材料说明库存团队备货与承运方配送，但未给各阶段正式问责人，`VS-4` 只记录"负责方"，不指定具体部门。

**与相邻方法的边界**：本方法定义"价值如何递进"，不定义"流程如何执行"。阶段先后是价值顺序，**不是**控制流或审批流；若需要描述步骤、分支与并行，应使用流程类工件而非价值流。

## 评审记录

- 核对受益者（`ST-1`）与最终价值（`V-1`）在阶段划分之前确定。
- 核对四阶段都有进入条件、退出条件与价值内容。
- 核对相邻阶段的"退出＝下一阶段进入"两两衔接，无空档。
- 核对 `C-2`、`C-4` 跨阶段复用同一 ID，未按阶段复制能力。
- 核对"验收"与"签收"被区分，`S-3` 与 `S-4` 各自成立。
- 核对争议处理在范围内，且 `S-4` 退出含争议解决分支。
- 核对没有把阶段先后解读为唯一流程实现或控制流。
- 核对缺口指向能力实例补充，未改成无关的性能指标。
- 核对三项修改情景说明"同一条价值流"与"新建价值流"的判别依据。
