# 从基线／目标差异形成可评审的差距

适用于 ADM B、C、D 的领域差距分析，以及 E 的跨域汇总。依据本地 G186 §5 的架构全景与现状／目标使用、§6.2–6.3 的权衡和影响可追踪要求，以及 G248 §2、§3、§8 的架构状态、模型与工作产品语境。下列字段和命令是项目实现约定，不是 TOGAF 强制算法。

## 比较输入

使用同一共享模型。分别为现状、每个过渡及目标注册 `states`，通过 `state_id` 引用；同一概念的各状态版本用不同实体 ID、相同 `concept_id`。`scope_id` 可由对象显式声明，也可继承命名状态。不同业务边界的同名概念不能因名称相同自动合并。

```bash
python skills/_shared/scripts/analyze.py model.json --compare \
  --baseline-state current --target-state target --scope business-unit
```

`current`、`target`、`business-unit` 替换为模型内真实 ID。可选择任一明确过渡状态作为比较端。CLI 先校验模型，再执行比较；未知状态／范围会失败，避免拼写错误变成整批删除候选。

## 读出差距

| 结果 | 处理 |
| --- | --- |
| `changed` | 阅读属性、名称、质量度量与关系差异；区分业务变化、记录完善及证据变更。 |
| `unchanged` | 本次选择中已对齐的模型内容无差异；不证明现实未变化或模型完整。 |
| `addition-candidate` / `removal-candidate` | 核对采集完整性及生命周期后，才决定新增、整合、替换或退役。 |
| `ambiguous-comparison` | 同一概念在某端有多个版本；收窄命名状态或修正概念身份。 |
| `incompatible-comparison` | 同一概念 ID 的类型冲突；确认是错误标识还是实际替换，不直接当作属性修改。 |
| `transition-only` | 当前选定两端都无记录；保留过渡版本，确认比较适用性。 |
| `unaligned_entity_ids` | 没有概念对齐的对象；应补身份或说明为何排除，不能计作已比较。 |

`attributes` 区分字段未提供与显式 `null`；`measurements` 保留单位、量表、测量方法、期间和证据，不自动相减或推断“改善”。`relationship_changes` 保留关系 ID、端点范围／类型、方向、代码、关系属性、基数和来源；不能只读兼容的 `relations_added` / `relations_removed` 概念投影。`transitions_to` 是版本转换，不计入业务依赖增删，过渡版本仍完整列出。

## 接入制品与迁移工作

1. 依据当前决策范围选择需要的目录、矩阵或图；保留两端可比较的视点及范围。修改的是同一模型，避免在输出文件中单独维护事实。
2. 将经判断的差距建为 `gap` 对象，记录受影响对象、目标需求／收益、处理选项、依据和未决项；用已注册关系连接领域对象，必要时用命名空间扩展明确额外语义。
3. 在 E 将差距归并为工作包，说明 ABB 要求和 SBB 候选；F 再给出资源、依赖、迁移波次和价值权衡。比较程序只提出事实差异，不自动创建已选方案或批准工作包。
4. 过渡状态核对业务连续性、数据一致性、控制、运营责任和回退。将同一分析引用到架构定义、路线图及需求影响评估，避免重复创造差距事实。
