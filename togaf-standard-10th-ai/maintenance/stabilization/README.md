# 本地工程修复轮次

本轮在 `codex/project-stabilization` 分支维护，不配置或推送远端。
初始本地资料清单记录大文件和保留资料的位置、大小与 SHA-256；不更改资料原字节。
源码、测试、维护脚本、锁文件和必要模型/检索清单进入 Git。运行证据、缓存、依赖二进制与归档留在本机，按 `.gitignore` 分类排除。

正式证据顺序：源码与测试冻结 → 来源闭包 → 封装及解包验证 → 完整工程验证与 507 项独立模型评测 → 当前入口切换 → 总报告 → 台账 → 完成状态 → 最终只读检查。

历史失败、旧报告和兼容覆盖层保留原字节；正式测试直接发现当前 `tests/test_*.py`，不加载历史覆盖层。后续修复以连续提交与新轮次证据追溯。报告和台账不作为上游执行输入。

范围是 UML 2.5.1、BPMN 2.0.2 完整设计时义务。台账登记、原字节保存、部分渲染器以及既有测试通过不等于完整标准支持。每项分别记录实现、正例、反例、往返与图形验证。独立模型复核、人工专业验收、真实组织批准单列；后两者保持待签署，直到取得实际签署。

评测沿用当前模型服务、模型及推理设置。正式活动仅在冻结、来源闭包、封装及渲染隔离验证通过后启动。最多四批，每批四小时与 1,000 会话，总计十六小时与 4,000 会话；中断、修复、重试与批间停顿沿用原预算。未执行、阻断、失败或过期版本均不计当前通过。
