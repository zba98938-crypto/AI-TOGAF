# 受控渲染输出发布与失败清理

本组修复独立实际审计发现的两个缺口：预置 PNG 链接导致已发布 SVG 残留，以及 `stat → unlink` 之间替换输出时可能删除替换项。旧攻击、运行日志和原始收据继续保存在各自不可变目录。

控制器先排他预留整套固定输出文件，再写入数据。冲突或写入失败时，将本次创建的目录项原子移到 Actor 无权访问的证据隔离目录；移动后核验设备号和 inode，匹配本次创建项才删除。不匹配项使用系统原生排他 rename 恢复，避免覆盖新占位。恢复冲突时隔离项保留原字节，任务返回 refused 且 cleaned=false；隔离项不进入任务临时目录的递归删除。跨文件系统 rename 失败也保留源项并报告清理失败。macOS `RENAME_EXCL=0x4` 与 `renameatx_np` 依据本机已安装 SDK 的 `usr/include/sys/stdio.h`；Linux 使用已有 libc 的 `renameat2/RENAME_NOREPLACE`，缺少原子操作时拒绝恢复。

独立最终审计引用 `output/native-data-di-independent-final-01/handoff.json`（SHA-256 `4e60cb21d4b9629a8bdf5398b2694fb0794b666c98449893a5f6251f01f00e36`）。实际 17 项边界测试无失败、错误或跳过；原生 Data DI 的两种实际渲染正例、22 种零 worker 拒绝、三个实际目标冲突、写入 17 字节后的 ENOSPC 注入、输出替换与恢复冲突、超时和取消回收均保留原始证据。最终只读核验检查 389 个证据目录项及九个源码文件。故障注入与自然压力执行分别记录；未创建新文件系统或额外软件。

统一零模型准入命令加入原生 Data DI 完整视图和部分所有者视图，并绑定生成它们的实际夹具源码。仍须在当前冻结版本执行 `diagnose_controlled_render.py` 与 `diagnose_controlled_bpmn_data.py`；本组审计不替代正式统一准入或 507 项评测。worker 超时从启动时计时，解析及字体准备时间单独体现在任务总时长；不宣称整个准备阶段具备相同的硬时间限。

模型调用、模型会话和预算变更均为零。完整 UML/BPMN 设计时能力、独立资料语义复核、507 项评测、人工专业验收和真实组织批准仍未完成。
