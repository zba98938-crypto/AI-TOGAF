## 作用范围与易误读处

成长上下文是适配架构服务的条件，不等于所有公司必须依次通过的同一认证等级；能力与服务不可混为一项。

## 项目应用建议

以下内容是基于本指南证据的建议。输入、输出与步骤不表示本项目已经具备或已经完成；采用前需要结合实际范围、约束和治理权责。

### 需要收集的输入

1. 企业成长上下文
2. 产品与客户反馈
3. 当前架构能力
4. 依赖、技术债务和风险

### 建议形成的输出

1. 按上下文选择的EA服务组合
2. 原则与制品裁剪
3. 架构能力发展方向
4. 下一成长阶段的预备事项

### 应用步骤

1. 识别个人/创始人、团队、团队之团队或持久企业上下文
2. 按决策需要选择可交付价值的EA服务
3. 把原则、制品及ADM实践裁剪到规模文化与运营
4. 管理跨团队依赖和技术债务，并预判下一上下文需求

### 决策与验收问题

1. 服务是否在当前上下文提供价值
2. 是否把历史文档要求当必需
3. 增长后依赖和风险是否可管理
4. 是否建立产品与用户反馈回路

## 概念与关系

概念：[企业架构服务](../concepts.md#ea_service)、[数字企业上下文](../concepts.md#digital_enterprise_context)。

- [R028](../relationships.md#r028)：企业架构服务 → `realization` → 企业架构能力；交付EA能力。
- [R029](../relationships.md#r029)：企业架构服务 → `mapping` → 数字企业上下文；按上下文选择服务。
